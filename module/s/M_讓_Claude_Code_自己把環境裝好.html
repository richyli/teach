讓 Claude Code 自己把環境裝好

在本單元中，會介紹怎麼指揮 Claude Code 把這台電腦的分析環境裝起來、怎麼確認它真的裝好了，以及卡住的時候要怎麼把問題描述清楚。

🎯 學習目標

# 你會的能力 讓你能解釋的真實問題
1 指揮 AI 完成一件你自己不會做的系統設定，並要求它把結果寫成一份文件 我完全不懂什麼是虛擬環境，為什麼我還是可以把它裝對？
2 描述一個技術故障，讓對方第一次回覆就能修 為什麼我說「它壞了」沒人理我，同學說一樣的事就有人幫他修好？
3 判斷它說「裝好了」是不是真的裝好了 它說完成了，但我怎麼知道它不是在唬我？

🤖 課前 AI 互動

請利用 AI 當成你的學習助理，請輸入下列提示：

我要在自己的電腦上做資料分析，會用到 Python 和 R。我完全沒有寫過程式。請先問我三個問題，確認我的作業系統和現在電腦上已經有什麼，然後再告訴我接下來會發生哪幾個步驟。每個步驟請用一句話說明它在做什麼、以及做完之後我會多出什麼東西。先不要給我任何指令，我只想先知道全貌。

它回答之後，再追問這一句：

這幾個步驟裡面，哪一步最常出錯？出錯的時候畫面上會出現什麼字？

當你拿到回答後，把它說「最常出錯」的那一步記下來，等一下跟同學比對——你們兩個的答案很可能不一樣，因為它是照你的作業系統回答的。

學生閱讀｜這一段你自己讀就懂

這一題沒有標準答案。重點是你在動手之前，先知道自己要走幾步路、每一步做完會多出什麼。不知道全貌就開始貼指令，出錯的時候你連自己走到哪裡都講不出來。

這一單元不教安裝步驟，教驗收標準

  • 安裝指令由軟體公司維護，改版很快；今天抄下來的指令，明年就對不上畫面。
  • 不會過期的是另外兩件事：你要它交出什麼，以及你怎麼確認它真的做到了。
  • 所以我們的作法是：把目標講清楚，讓它自己想辦法，然後驗收。

你不需要知道怎麼裝，你需要知道裝完之後應該長什麼樣子。這跟你請水電師傅來家裡是同一件事——你不必會接線，但你要會開燈確認。

你要它做的五件事

  • 這五件事是一整個學期只做一次的開場，做完就不必再碰。
  • 五件事有順序，前一件沒成功，後面會連環失敗。
  • 最後一件是驗收，它是整段裡唯一不能跳過的。

請新開一個資料夾，在裡面啟動 Claude Code，把下面這段整段貼進去：

我要做這門課的資料分析，會用到 Python 和 R，我不會寫程式。請依序完成以下五件事，每完成一件就告訴我結果： 一，偵測我的作業系統、Python 和 R 的位置與版本，如果找不到就告訴我還沒裝。 二，把偵測結果寫成這個資料夾裡的 ENVIRONMENT.md，內容包含每一項的完整路徑。 三，建立一個虛擬環境，Windows 請建在 C:/cvenv，Mac 請建在家目錄底下的 cvenv，然後安裝 pandas、numpy、matplotlib、jupyter。 四，找出 Rscript 的完整路徑，寫進 ENVIRONMENT.md，並產生一個叫做 run_r 的包裝腳本，讓我以後不必打那串很長的路徑。 五，寫一支 verify_env 的小程式並執行它，逐項印出綠燈或紅燈，包含 Python 版本、每一個套件、以及 R 能不能被叫動。 過程中如果需要我的權限，或需要我做決定，請先停下來問我。不要自己修改系統設定、不要改 PATH、不要動系統內建的 Python。

最後一句是整段裡最重要的一句

  • 它有能力改你的系統設定，而且改壞了你不會知道。
  • 需要權限的時候停下來問你，你才有機會說不。
  • 這條界線不是這門課特有的規矩，是你以後用任何 agent 都該畫的線。

一個會自己動手的 AI，跟一個只會回你文字的聊天框，差別就在它真的會改你的電腦。方便和風險是同一件事的兩面。你現在畫的這條線，之後每一次用它處理公司檔案、處理真實資料，都還會再用到。

放手讓它做，不等於讓它做任何事。界線要在它動手之前講，不是出事之後補。

三條規定，兩行指令就能省掉三種災難

  • 虛擬環境建在短路徑，可以避開 Windows 的路徑長度限制。
  • 專案資料夾不要放在雲端同步資料夾、不要放桌面、路徑不要有中文和空白。
  • 這兩條加起來，就擋掉了初學者最常撞的三種錯誤。
規定 怎麼做 不照做會發生什麼
虛擬環境放短路徑 Windows 放 C:/cvenv，Mac 放家目錄的 cvenv 套件裝到一半失敗，而且失敗訊息完全看不懂
專案資料夾放短路徑 Windows 放 C:/kmg，Mac 放家目錄的 kmg 雲端同步會把檔案鎖住，程式讀不到
路徑不要有中文和空白 資料夾名字用英文小寫 有些工具會在中文路徑上直接爆掉
學生閱讀｜為什麼是這三條

這三條不是原理，是經驗。你現在照做就好，等你撞到別台電腦上的怪問題，會回頭想起這三行。

卡住的時候怎麼講，決定你要卡多久

  • 「不能跑」「壞了」「有錯誤」這三句話送出去，等於什麼都沒說。
  • 一次講三件事：我做了什麼、它回了什麼、我的環境長怎樣。
  • 錯誤訊息要貼開頭和結尾，不要只貼最後那一行紅字。

求救的時候照這個順序講：

  1. 我剛剛做了什麼：把你打的指令原封不動貼上，不要重打一次。
  2. 它回了什麼：錯誤訊息貼開頭二十行和結尾二十行。真正的原因常常在開頭，最後一行只是結果。
  3. 我的環境：把 ENVIRONMENT.md 整份貼上。

然後固定加這一句收尾：

請先講你判斷的原因，再給一個最小的修法，不要一次改三個地方。改完告訴我怎麼確認有修好。

為什麼要它「一次只改一個地方」

  • 一次改三個地方，修好了你也不知道是哪一個奏效。
  • 下次再壞，你還是只能從頭來一次。
  • 這個要求跟做分析是同一個道理：一次動一個變因，才知道是誰造成的。

怎麼知道它真的裝好了

  • 它說「完成了」不算數，能跑出綠燈才算。
  • 驗證要驗到「能做出你真正要做的事」，不是只驗「檔案存在」。
  • 綠燈之外還要留下一份文件，下次壞掉才有東西可以對照。

驗收清單，三項都要親眼看到：

要驗什麼 通過的樣子
每一個套件都真的裝起來 verify_env 逐項印出綠燈，沒有紅燈
R 叫得動 用 run_r 跑出一行 R 的版本資訊
留下可以對照的紀錄 資料夾裡有 ENVIRONMENT.md，裡面每一項都有完整路徑

它說裝好了是它的說法，綠燈是證據。以後每一次它說「完成」，你都要問一句：拿什麼證明？

⚠️ 迷思攔截

這張表是這一段最容易誤會的幾件事。

常見迷思 為什麼太簡化 攔截
「我不會寫程式，所以裝不起來」 安裝跟寫程式是兩件事。你要做的是描述目標與驗收，不是打指令 你的工作在前端（說清楚要什麼）和後端（確認做到了）
「它說完成了就是好了」 它判斷「完成」的依據是指令有沒有報錯，不是東西能不能用 一律要求跑驗證腳本，看綠燈
「裝不起來代表我電腦爛」 多數卡點是權限、路徑、版本三件事，跟電腦好壞無關 把錯誤訊息完整貼給它，它多半兩三輪就能修
「出錯就重來一次」 重來會蓋掉現場，下次同樣的錯還是不會修 先把錯誤訊息存下來，再重來
「環境裝好就一勞永逸」 換電腦、換學期、套件更新都會再壞一次 留著 ENVIRONMENT.md，下次直接貼給它當起點

先修與後續

  • 先修：Claude Code 上手——沒有它，你不知道要在哪裡打字、也不知道權限模式在問什麼。
  • 後續：第一次讓 AI 讀一張表——環境裝好之後，第一件事就是拿它讀一份真的資料。
  • 想多練：Hub - 資料分析練習案例庫——整條分析線的地圖與十九個可以自己做的案例。
  • 平行相關：AI 在數據分析的角色與限度——本單元的「驗收」動作，就是那一節「要算式、對分母、查來源」的前一步：先確認工具是好的，再確認數字是對的。

小結論

你現在可以指揮一個 AI 完成一件你自己不會做的事，並且知道怎麼驗收它。三件事帶走：目標和驗收標準要自己講清楚，因為那是不會過期的部分；需要權限的時候它必須停下來問你，這條線由你來畫；它說「完成」不算數，綠燈才算數。這三件事在接下來每一個單元都會再用到——只是對象從「裝環境」換成「算數字」。

配對分享

情境：兩個同學同時要裝環境。小葳用的是自己的筆電，Windows 系統，習慣把所有檔案都放在桌面，桌面又設定成自動同步到雲端硬碟；她的中文使用者名稱讓資料夾路徑裡有中文字。阿哲用的是公司配的筆電，Mac 系統，公司資訊部門把他的帳號設成沒有管理員權限，安裝任何東西都會跳出要輸入密碼的視窗，而他沒有那組密碼。兩個人都在同一堂課、貼了同一段提示、跑到第三步就停住了。小葳的畫面出現一串紅字，最後一行寫著找不到路徑；阿哲的畫面則是停在一個要求輸入密碼的提示上，游標一直閃。

請同學兩兩一組，一人扮演小葳、一人扮演阿哲：

  1. 各自替自己那個角色寫出一則求救訊息，照「我做了什麼、它回了什麼、我的環境」三段式，最後加上那句固定收尾。
  2. 交換，讀對方寫的那一則，指出它缺了三段裡的哪一段。
  3. 一起判斷：這兩個人卡住的原因，哪一個靠改提示就能解決，哪一個非得先去找人不可？並各自引用情境裡讓你這樣判斷的那一句話。

第 3 題有明確答案，兩邊的根據都寫在情境裡：阿哲缺的是權限，那是人的問題不是提示的問題，因為情境寫了他沒有那組密碼；小葳的路徑問題可以靠換資料夾位置解決，因為情境寫了桌面自動同步、而且路徑裡有中文。

〔加碼選項：你自己的電腦如果剛好卡住了，換成你的真實情況再跑一次。〕

小作業

把你電腦上的 ENVIRONMENT.md 交上來，並在最後補一段：你卡住過的地方、你當時怎麼描述它、後來是怎麼過的。完全沒卡住的人，寫下你覺得下一次最可能壞在哪一項，以及你打算怎麼確認。
