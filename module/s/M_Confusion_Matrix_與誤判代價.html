Confusion Matrix 與誤判代價

🎯 學習目標

每條目標都是「一項能力 → 能解釋一個真實問題」。學這個不是為了看懂一張表格，是為了不被「準確率 95%」這種數字騙過去。

# 你會的能力 讓你能解釋的真實問題
1 解釋 confusion matrix 四格的意思，以及 false positive 與 false negative 的差別 為什麼「準確率 95%」可能是個騙局？如果 100 則裡只有 5 則是假新聞，全部判「真」也有 95% 準。
1b 說出 accuracy／precision／recall／specificity／F-score 各自的分母是哪一格，以及各自看不到什麼 工程師報告時丟出五個數字，我要盯哪一個？為什麼兩個完全相反的系統，F-score 可以一模一樣？

3 拆解一個真實 AI 決策的兩種誤判各害到誰，並權衡門檻 為什麼自動假訊息偵測一上線就被罵爆？——把「漏掉假訊息」和「誤刪真報導」的代價攤開，會發現新聞場景的 FP 比 FN 更傷可信度。選門檻＝替你的場景決定『寧可錯抓還是寧可放過』。

Confusion Matrix 的四格

任何「把東西分成兩類」的 AI——這則貼文是不是假訊息？這則留言該不該刪？——上線後只會有四種結局。把它畫成一張 2×2 的表，就是 confusion matrix（混淆矩陣）。

拿一個你天天會碰到的場景：一套假訊息偵測系統，掃過 100 則貼文，每一則它判「假」或「真」，而每一則實際上也真的是「假」或「真」。把「系統怎麼判」當欄、「實際是什麼」當列，就得到四格：

實際是假訊息 實際是真消息
系統判「假」（攔下來） ✅ TP 真陽性：假的，抓對了 ❌ FP 偽陽性：真的，被誤刪／誤標
系統判「真」（放行） ❌ FN 偽陰性：假的，漏掉了 ✅ TN 真陰性：真的，正確放行

逐格用白話講一遍：

  • TP（True Positive，真陽性）：是假訊息，系統也說是假訊息。抓對了。
  • FP（False Positive，偽陽性）：其實是正當報導，系統卻把它當假訊息攔下來。冤枉好人——真記者的稿被下架、真讀者被禁言。
  • FN（False Negative，偽陰性）：是假訊息，系統卻放它過去。漏網之魚——假消息照樣傳播。
  • TN（True Negative，真陰性）：是真消息，系統也放行。沒事。

兩條對角線是兩種人生：左上＋右下（TP＋TN）是答對，右上＋左下（FP＋FN）是兩種不同的錯。整個模組的重點就是：這兩種錯不一樣，代價也不一樣。

兩個你必須聽得懂的詞：precision 與 recall

工程師報告時會丟出兩個指標。你不用會算，但要聽得懂它們各自只看哪一格的失敗：

  • 精確率 precision（白話：抓出來的，有多少是真的該抓的）——系統喊「假訊息」的那一堆裡，有多少真的是假訊息？被它「冤枉」越多，precision 越低。
$$\text{precision}=\frac{TP}{TP+FP}$$
  • 召回率 recall（白話：該抓的，抓到多少）——所有真正的假訊息裡，被系統抓到的比例。漏掉越多，recall 越低。
$$\text{recall}=\frac{TP}{TP+FN}$$

記法：precision 在替「被你攔下來的人」喊冤（盯 FP）；recall 在替「被你放過去的禍害」算帳（盯 FN）。 一個顧誤殺，一個顧漏網。

兩種錯的正式名字：Type 1 與 Type 2 Error

統計課本裡的講法，跟這張表是同一件事，只是換個名字：

  • FP＝Type 1 Error（型一錯誤）：本來沒事，你說有事。偽陽性、false alarm、冤枉好人。
  • FN＝Type 2 Error（型二錯誤）：本來有事，你說沒事。偽陰性、漏網之魚。

聽到工程師或研究者講「型一錯誤」，就把它翻成「誤抓」；「型二錯誤」翻成「漏掉」。

五個數字，先把定義弄清楚

工程師的報告上通常有五個數字。每一個的分母不一樣，因此每一個都有它看不見的東西。

指標 公式 白話 分母是哪一塊 它看不見什麼
Accuracy 準確率 $\dfrac{TP+TN}{總數}$ 全部判斷裡判對的比例 全部四格 看不見兩種錯的差別；當陽性極少時會嚴重高估
Recall 召回率 $\dfrac{TP}{TP+FN}$ 該抓的抓到幾成 「實際為陽性」那一列 看不見你誤抓了多少
Precision 精確率 $\dfrac{TP}{TP+FP}$ 抓起來的有幾成是對的 「判為陽性」那一欄 看不見你漏掉了多少
Specificity 特異度 $\dfrac{TN}{TN+FP}$ 本來沒事的，有幾成被正確放行 「實際為陰性」那一列 看不見陽性那一側的表現
F-Score（F1） $\dfrac{2PR}{P+R}$ precision 與 recall 的調和平均 — 看不見兩者是誰高誰低——兩個相反的系統可以同分

recall 與 specificity 是一對鏡像：一個顧陽性那一列（有沒有漏），一個顧陰性那一列（有沒有冤枉）。 在陽性極少的場景（詐騙、疾病、假訊息），specificity 幾乎永遠很漂亮，因為分母被大量的 TN 撐著—— 所以看到很高的 specificity 不必太興奮，那多半是題目本身給的。

模型判為「是」模型判為「不是」

用一個古典難題算一次：To kill, or not to kill

「寧可放過十個有罪的人，也不要讓一個無辜者受害。」——William Blackstone

一百個被告，其中五個真的有罪。系統判決的結果：

判有罪（處死） 判無罪（釋放）
真的有罪 TP = 3 FN = 2
真的無辜 FP = 4 TN = 91

代進去算：

  • Accuracy $=(3+91)/100=\mathbf{94\%}$
  • Recall $=3/(3+2)=\mathbf{60\%}$
  • Precision $=3/(3+4)=\mathbf{42.9\%}$
  • Specificity $=91/(91+4)=\mathbf{95.8\%}$
  • F1 $=\mathbf{0.50}$

準確率 94% 聽起來不錯，但有四個無辜的人被處死，而且只抓到六成的真兇。 Blackstone 那句話的意思，用今天的語言講就是：FN 的代價權重應該遠低於 FP。

同樣的準確率，兩個相反的世界

現在看兩個極端。兩者的 accuracy 都是 91%，F-score 都是 0.1818：

高偽陽（寧可錯殺） 高偽陰（寧可錯放）
TP / FN / FP / TN 1 / 0 / 9 / 90 1 / 9 / 0 / 90
Recall 100% 10%
Precision 10% 100%
Specificity 90.9% 100%
實際發生了什麼 一個有罪的都沒放過，九個無辜者被處死 沒有冤枉任何人，九個有罪的被放走

這是這一堂最重要的一張表。 同樣的 accuracy、同樣的 F-score， 一個是獨裁者的世界，一個是 Blackstone 的世界。 任何把兩種錯壓成單一分數的指標，都會把這個差別抹掉。

極端的準確率：恐怖份子

每年一千萬人入境，其中十名恐怖份子。系統攔下五名、放行五名，一般旅客零人被錯攔：

  • Accuracy $\approx \mathbf{99.99995\%}$
  • Precision $=\mathbf{100\%}$（攔下來的全對）
  • Specificity $=\mathbf{100\%}$（沒有冤枉任何旅客）
  • Recall $=5/10=\mathbf{50\%}$

四個數字裡有三個接近完美，但一半的恐怖份子入境了。 這是「準確率會騙人」最乾淨的例子——陽性佔比只有百萬分之一時，準確率這個指標基本上沒有資訊量。

confusion matrix 不是一個分數，是四種結局——而其中兩種『錯』，從來不等價。

學生閱讀｜這一段你自己讀就懂

一個會做「是／不是」判斷的系統，結果只有四種：抓對、抓錯、漏掉、正確放過。 把它們排成兩排兩列，就是 confusion matrix。

從這四格衍生出兩個你一定要聽得懂的詞：

  • recall（抓到幾成）：真的有問題的東西裡，它抓到多少。漏得少，recall 就高。
  • precision（抓的對幾成）：它抓起來的東西裡，真的有問題的佔多少。誤抓得少，precision 就高。

關鍵在於：這兩個數字沒辦法同時衝高。 想少漏一點，就得放寬標準，於是誤抓變多； 想抓得準一點，就得提高標準，於是漏得更多。你只能選一邊，而選哪一邊不是技術問題， 是「哪一種錯，我們賠得起」的問題。

誤判代價不對稱

先做一個選擇題：Google 還是 Yahoo？

兩家的垃圾信過濾器，各測兩千封信（一千封垃圾、一千封正常）：

Google Yahoo
TP（垃圾信抓到） 990 950
FN（垃圾信漏掉） 10 50
FP（正常信被誤殺） 20 1
TN（正常信放行） 980 999
Accuracy 98.5% 97.45%
Recall 99.0% 95.0%
Precision 98.0% 99.9%
Specificity 98.0% 99.9%

哪一個比較強？ Google 的 accuracy 與 recall 都比較高，如果只看那兩個數字，答案很明顯。

但是把兩種錯換成真實後果：

  • FN（漏掉垃圾信）＝使用者信箱裡多幾封廣告，煩，但按一下就刪掉了。
  • FP（正常信被丟進垃圾桶）＝使用者錯過一封重要的信，可能是客戶、面試通知、法院文書。

Google 誤殺 20 封，Yahoo 誤殺 1 封。在這個場景，FP 的代價高出 FN 好幾個量級， 所以 accuracy 比較低的 Yahoo，很可能才是使用者要的那一個。

這一題要記住的不是誰贏，是「哪一個模型比較強」這個問題本身沒有答案—— 沒有先講清楚兩種錯的代價，任何比較都是空的。

先戳破「準確率 95%」的迷思

工程師說：「我們這套假訊息偵測，準確率 95%。」聽起來很猛。但請先問一句：這批資料裡，假訊息本來占多少？

假設 100 則貼文裡，只有 5 則是假訊息，95 則是真的。現在我做一個最廢的「模型」：不管三七二十一，全部判「真」。

  • 95 則真消息，全判真 → 全對（95 個 TN）。
  • 5 則假訊息，全判真 → 全錯（5 個 FN）。
  • 答對 95 / 100 = 準確率 95%。

一個什麼都沒做、假訊息一則都沒抓到的廢模型，準確率就有 95%。這叫 base rate（基準率）陷阱：當你要抓的東西本來就很稀有，「準確率」這個單一數字幾乎只是在反映「多數類有多大」，跟「有沒有抓到壞東西」幾乎無關。

這時候真正會說話的是 recall：上面那個廢模型 recall = $\frac{0}{0+5} = 0$，一抓就現形。所以主管聽到「準確率 95%」的正確反應不是點頭，是反問：「那 recall 多少？漏掉的那批呢？」

同一個 95%，FP 和 FN 的代價天差地遠

兩種錯的代價幾乎從不對稱，而且害到的是不同的人。同一套「準確率」，換個場景，你該怕的錯就翻面：

場景 FP（誤抓／誤判正向）害到誰 FN（漏抓／漏判）害到誰 哪種代價更高
假訊息偵測 真記者好稿被下架、真讀者被禁言 → 傷新聞可信度與言論自由 假消息照傳 → 公共危害、平台被罵 視角而定，但新聞品牌通常更怕 FP（誤殺真報導重傷公信力）
留言審查 正常網友被誤封、社群氣氛變寒蟬 攻擊／仇恨言論漏放 → 受害者受傷、平台失格 FN 漏放仇恨對受害者代價極高；但 FP 過嚴會趕走用戶
內容推薦 推了用戶其實沒興趣的內容 → 體驗稍差 該推的好內容沒推到 → 機會成本、流量損失 兩者代價都相對低、可逆，容錯空間大
詐騙偵測 正常交易被擋、用戶氣到客訴 詐騙放過 → 真金白銀損失、法遵風險 FN 漏掉詐騙通常代價最高（直接賠錢＋監管）

讀這張表的方式：先問「在我的場景，FP 和 FN 各害到誰、賠不賠得起、可不可逆」，再決定要把系統調得「寧可錯殺」還是「寧可錯放」。留言審查漏放一則仇恨言論，傷的是一個具體的受害者，可能不可逆；推薦系統推錯一則，使用者滑掉就沒事。代價結構不同，工程上該追求的指標就不同。

『準確率 95%』是句空話，除非你先問清楚——這 5% 的錯，是冤枉好人（FP）還是放過壞人（FN），而我的場景賠得起哪一種？

💬 兩人一組：先各自拉，再說服對方

每題都先各自把門檻拉到你認為對的位置、記下四格數字，再互相說明理由。重點不是誰對，是你用什麼理由決定「寧可錯抓還是寧可放過」。

  1. 哪些情境你會把 recall 拉到最高？拉到最高之後看 precision 掉到多少、FP 變成幾件——你的團隊吃得下這些誤抓的後續處理嗎？
  2. 哪些情境 precision 必須最高？把門檻拉到 precision 最高的位置，看 FN 變幾件。那些被放過的，後果由誰承擔？
  3. 「準確率 95%」在哪個情境下最會騙人？把真陽性比率拉到 1%，門檻拉到最右（幾乎什麼都不抓），看 accuracy 剩多少、recall 剩多少。
  4. 同一種技術，方向相反：切到「AI 生成投稿偵測」與「送稿照片變造偵測」，兩個都是判斷「這東西是不是機器做的」，但一個直接退稿懲處、一個只是送人工複核。分別按「幫我找總代價最低的門檻」，看兩邊的 recall 差多少。決定方向的不是技術，是這個判斷後面接著什麼流程。
  5. 單價低就沒事嗎？切到「訂戶流失預測」，誤發一封挽留信只要 3 分，但把門檻拉低看誤發總件數變幾萬。什麼時候「便宜的錯誤」會變成大問題？
  6. 換一個角色再答一次：同一個假訊息偵測，你是總編輯 vs 你是平台法遵主管 vs 你是被誤刪的記者——三個位置會把門檻拉到同一格嗎？
  7. 校對系統做到幾成才停？用下面那個成本面板：先各自決定「一個錯字被讀者看到，值多少錢」，再看你們算出來的合理投資上限差多少。品牌損失是最難估也最能吵的一個數字——你憑什麼說它是 200 而不是 20？
  8. 模型變好，兩難就消失嗎？把「模型鑑別力」從 0.5 拉到 3.0，precision 與 recall 是不是能同時變好？那為什麼還是得選門檻？
可用的判準，不是答案：
① 哪一種錯不可逆——漏掉一個早期癌症、放過一則選前假訊息，事後補不回來；誤抓通常可以申訴、可以復原。不可逆的那一邊，就是要壓低的那一邊。
② 誰承擔後果——FP 的代價常落在被誤判的個人（記者被下架、店家被封），FN 的代價落在整個公眾。落點不同，不能用同一個總分衡量。
③ 後面有沒有人接——若有人工複核當第二關，可以把 recall 拉高、讓機器多抓一點；沒有人力複核就把門檻拉高，否則等於用 FP 淹死自己的團隊。
④ 量級——真陽性比率越低，同樣的 FPR 會製造越多 FP。1% 盛行率下，看起來很小的誤判率會讓 precision 崩掉。
⑤ 模型變好也不會取消選擇——鑑別力提高會讓整條取捨曲線往外移，兩個指標可以同時變好，但只要兩個分布還有重疊，你就還是得決定門檻站哪裡。這是價值判斷，不是技術問題。
學生閱讀｜為什麼「準確率 95%」常常是句空話

假設一萬則貼文裡只有 500 則是假訊息。有一個系統什麼都判「不是」， 它的準確率是 95%——因為 95% 的貼文本來就不是假訊息。但它一則都沒抓到。

所以聽到「準確率 95%」時，該問的是：這 5% 的錯，是冤枉好人還是放過壞人？ 我們的場景賠得起哪一種？ 只看一個總分，等於什麼都沒問。

把代價換成錢：銀行房貸的成本矩陣

指標吵不出結論的時候，把四格換成金額，答案通常就出來了。

一家銀行的貸款申請：95% 的人會準時還款，每人帶來 1,000 元利潤；5% 會違約，每件損失 50,000 元。

核貸 婉拒
會準時還（95%） TP：+1,000 FN：0（少賺 1,000 的機會成本）
會違約（5%） FP：−50,000 TN：0（避開損失）

一筆違約的損失，等於五十筆正常放款的利潤。所以即使違約者只佔 5%， 寧可錯拒五十個好客戶，也不要放行一個違約戶——門檻自然應該往嚴的那邊調。

換成媒體場景是同一個算法：一則誤刪的報導要花多少人力善後、賠掉多少記者信任？ 一則漏掉的假訊息會造成多少公信力損失？兩個數字算出來，門檻就不必用感覺決定。

（下一個工具就是在做這件事——它把兩種錯的代價權重放進去，直接幫你找總代價最低的門檻。）

主管視角：該問工程師什麼、門檻調哪邊

precision / recall 的拉鋸：門檻（threshold）

模型其實不是直接吐「假／真」，而是吐一個分數（例如「這則是假訊息的機率 0.73」）。是你（或工程師）設一條門檻，超過就判「假」、攔下來。這條門檻往哪邊移，就決定了你要哪一種錯。

  • 門檻調低（風吹草動就攔）：抓得更兇 → 漏網變少（recall ↑），但冤枉的也變多（precision ↓）。寧可錯殺。
  • 門檻調高（很確定才攔）：出手更謹慎 → 冤枉變少（precision ↑），但漏網變多（recall ↓）。寧可錯放。

這是一場蹺蹺板：在同一個模型上，precision 和 recall 通常無法同時拉滿，壓低一種錯就會放大另一種。所以「門檻定在哪」不是技術細節，是價值判斷——你在替你的場景決定「寧可錯抓還是寧可放過」。這正是該由懂業務、懂品牌風險的主管參與的決定，不該全丟給工程師。

評估一個模型，不是只有準確度

工程師報告時容易只談指標。主管要記得問的還有五件事，它們不在 confusion matrix 上：

面向 該問的問題
速度 Speed 一則要判多久？尖峰時段跟得上嗎？
穩健 Robustness 換一種寫法、換一個議題，它還準嗎？
可擴充 Scalability 量翻十倍時成本怎麼變？
可解釋 Explainable 它為什麼判這一則？申訴的人問起來，我們答得出來嗎？
維運 誰每週看它有沒有漂掉？壞掉怎麼知道？

可解釋那一項對媒體特別致命：被誤刪的記者一定會問「為什麼」， 「模型說的」不是一個可以拿出去的答案。

該問工程師的三題

不用會算，把這三題問出口，你就已經不會被單一數字騙：

  1. 「誤判率多少——precision 和 recall 各是多少？」（別接受只報一個「準確率」。要拆開看冤枉率和漏網率。）
  2. 「在我們這個場景，哪一種誤判代價高——FP 還是 FN，害到的是誰？」（逼大家把「冤枉好人」和「放過壞人」攤開比，這是業務判斷不是技術判斷。）
  3. 「門檻怎麼定的、能不能調？如果我們更怕漏掉假訊息，門檻往哪邊移、代價是什麼？」（確認門檻是可調的旋鈕，而且調整的取捨講得清楚。）

設「人複核把關點」：human-in-the-loop

既然兩種錯都消不掉、門檻只能在它們之間取捨，成熟的設計不是「讓模型全自動」，而是把人放在最痛的那種錯的關口上——這就是 human-in-the-loop（人機協作把關）。設計原則：

  • 不對稱投放人力：哪種錯代價高、不可逆，就在那條路徑上塞人工複核。例如假訊息偵測怕誤刪真報導（FP），就讓系統只「標記送審」、下架前一定要編輯人工確認；詐騙偵測怕漏掉（FN），就把模型門檻調低多攔、再讓人去清冤枉的那批。
  • 用門檻分流，不是門檻決生死：高信心的自動處理、模糊地帶（接近門檻）一律送人複核。讓 AI 處理量、讓人處理風險。
  • 記錄與回饋：人複核的每一筆都是在告訴模型「這格你判錯了」，回頭可以重新校準門檻與重訓。

延伸閱讀（這套思路在治理層怎麼落地）：編輯室 AI 治理與揭露。

真實個案（效率數字如何蓋住誤判代價）：DOGE 用 AI 砍法規而政府拒絕揭露 — DOGE 宣稱 AI 把法規審查「快 90%（36 小時→2.4 小時）」，但把「錯刪一條反歧視住房法規」與「漏刪一條冗規」的極不對稱代價整個藏了起來。是「當有人拿效率數字說服你導入 AI，先問代價換的是什麼」最好的討論素材。

這一堂收束成一句話：模型給你分數，門檻替你的場景決定『寧可錯抓還是寧可放過』，而人複核把關點要設在你最賠不起的那種錯上。AI 負責量，人負責風險。

⚠️ 迷思攔截

聽工程師報告時，這三句話只要出現就要警鈴大作：

迷思 為什麼錯 怎麼攔截
「準確率高就是好模型」 在 base rate 偏斜的場景（假訊息稀有），全判「真」也有 95% 準——準確率只反映多數類大小，沒告訴你抓到壞東西沒 反問「recall 多少、漏掉的那批呢」；要求拆出 precision／recall 而非只看一個總分
「precision 和 recall 可以同時拉滿」 同一模型上兩者是蹺蹺板，壓低一種錯就放大另一種；門檻往哪移都得犧牲一邊 要工程師畫出「不同門檻下 precision／recall 怎麼變」，逼出取捨而非幻想全贏
「門檻是工程師的事，跟我無關」 門檻＝「寧可錯抓還是寧可放過」的價值判斷，牽涉品牌風險與對誰負責，是業務決定不是技術細節 主管必須參與定門檻，並指定「哪種錯我們更賠不起」；把它當經營決策而非調參

與其他模組的關係

  • 偏見從哪來：模型為什麼系統性地對某類內容判錯（某一格特別高），常是訓練資料的問題 → Data Bias 資料偏誤、深度學習與 LLM 偏見來源。
  • 怎麼落地成制度：門檻、人複核把關點、誤判責任歸屬，要寫進編輯室規範與對外揭露 → 編輯室 AI 治理與揭露。
  • 放進主管決策框架：「驗收 AI 別只看一個數字」是主管面對所有 AI 系統的通則 → AI 地景與主管決策框架。
