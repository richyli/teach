Case: Productizing Your Own Workflow

案例：把自己的工作流程產品化

For 2026 Product Planning Syllabus (W1 PM role, W2/W10 AI craftsmanship). Unlike the two hackathon cases (Case - Claude Build Day Hackathon, Case - Opus 4.7 Claude Code Hackathon), this is a real, internal, long-run workflow — a non-coder turning his own job into products. Also relevant to EMA (媒體主管導入) and Web Analytics (data-driven outreach). 與兩篇 hackathon 案例不同，這是真實、內部、長期的工作流——一個不會寫程式的人把自己的工作變成產品。對 EMA、Web Analytics 也有用。 Source 來源：How Anthropic uses Claude: GTM engineering

What happened 發生了什麼

EN — Jared Sires joined Anthropic in 2024 as a salesperson who had never written code. Doing 10–15 customer calls a day, he spent 9–10pm every night on email — "basically impossible to manage the inbox." Using Claude Code, he built a series of tools that productized his own workflow, then scaled them to the whole sales team. His role evolved from salesperson to GTM (go-to-market) product manager.

中 — Jared Sires 2024 年加入 Anthropic 當銷售，從沒寫過程式。每天 10–15 通客戶電話，每晚 9–10 點還在處理郵件——「基本上不可能管理收件匣」。他用 Claude Code 做了一系列工具，把自己的工作流程產品化，再擴散到整個銷售團隊。他的角色從銷售演進成 GTM 產品經理。

The tools he built 他做的工具

工具 做什麼 用到的 Claude 功能
CLAFTS（Claude Drafts） 在 Gmail 內用 Claude API 草擬客戶回覆，~4,300 行幾乎全由 Claude Code 寫；數百次系統提示迭代到符合本人風格；CLAFTS Tones 依關係（客戶/同事/家人）切換語氣。每天省 2–3 小時 Claude API、Claude Code
Daily Brief 每早讀日曆、跑網路搜尋、生成會議談點；按使用量排序 700 個帳戶決定外聯重點 MCP（Google Calendar + CRM）、Web Search
Daily Recap 從 Google Docs 與會議筆記草擬後續郵件 Skills、Agent SDK
Sales Plugin 打包進 Claude Cowork，推出數月內 80% 銷售人員採用。/customer-context 90 秒匯整 Salesforce/Intercom/Gong/Calendar/Gmail/Drive/BigQuery 的 360 度客戶視圖；/pipeline-management 呈現風險交易與預測 Claude Cowork、MCP、Skills

Lessons, mapped to the syllabus 心得，對應課綱

1. The PM role evolves: from executor to designer｜PM 角色演進：從執行者到設計者

→ W1 (PM role)

EN — "Once the technical barrier dissolved, I could design more products, with senior engineers helping with the last mile." A non-coder became a product builder. This is the literal thesis of W1 — Agentic AI reshapes the PM's day-to-day and widens who can build. 中 — 「技術障礙消融後，我能設計更多產品，由資深工程師協助最後一哩。」一個不會寫程式的人變成產品建構者。這正是 W1 的命題——Agentic AI 重塑 PM 日常、擴大「誰能建造」。

2. Start from one task that slows you down｜從一個拖慢你的具體任務開始

→ W2 / W10 (AI skill craftsmanship), AI Skill Sharing assignment

EN — His advice: "Open Claude Code, find a task that slows you down, ask Claude how to build a solution." Don't start from a grand product — start from your own friction. This is exactly the course's AI Skill Sharing assignment. 中 — 他的建議：「打開 Claude Code，找一個拖慢你的任務，問 Claude 怎麼做解法。」不要從宏大產品開始，從自己的摩擦點開始。這就是課程的 AI Skill Sharing 作業。

3. Validate personally, then scale to a plugin｜先個人驗證，再擴散成插件

→ W1 lifecycle / W16 (deployable product)

EN — He proved value on himself (adopted within 24 hours of a Slack post), then packaged the winners into a company-wide plugin designed for new hires to install on day one. Personal tool → validated → productized → distributed: a full lifecycle in miniature. 中 — 他先在自己身上驗證價值（Slack 貼出 24 小時內被採用），再把成功的打包成全公司插件、設計成新人第一天就能裝。個人工具 → 驗證 → 產品化 → 分發：一條微縮的完整生命週期。

4. Iterate the system prompt to match a voice｜用數百次迭代讓輸出符合風格

→ W10 (calibrated trust) / inscription

EN — CLAFTS took hundreds of system-prompt iterations to match his writing voice and switch tone by relationship. The craft is in the iteration, not one perfect prompt. 中 — CLAFTS 經數百次系統提示迭代才符合他的文風、依關係切換語氣。工藝在迭代，不在「一次寫出完美 prompt」。

5. Web search beats stale knowledge bases｜即時搜尋勝過過時知識庫

→ Web Analytics / EMA — data freshness

EN — The product updated every 24–48 hours; instead of a knowledge base that lags, Claude used live web search to stay accurate. A real answer to the classic "our docs are always out of date" problem. 中 — 產品每 24–48 小時更新；與其用會滯後的知識庫，Claude 用即時網路搜尋保持準確。這是對「文件永遠過時」老問題的真解。

6. Efficiency frees creative & strategic work｜效率解放創意與策略工作

→ course thesis / W12 (saying no to busywork)

EN — Freed from 9–10pm admin, he spent more time actually selling and designing. "I have room to work more creatively and strategically. Can't go back." The point of automating the rote is to reclaim judgement work. 中 — 從每晚 9–10 點的行政工作脫身後，他有更多時間真正銷售與設計。「我有空間更有創意、更策略地工作，回不去了。」自動化雜務的目的，是把時間還給判斷型工作。

One-line takeaway 一句話總結

EN — You don't need to be an engineer to build products with AI — you need to find your own friction, productize the fix, validate it on yourself, then scale it. The PM's new job is to design solutions, and the technical last mile is increasingly cheap. 中 — 不必是工程師也能用 AI 做產品——你要找到自己的摩擦點、把解法產品化、在自己身上驗證、再擴散。PM 的新工作是設計解法，而技術的最後一哩愈來愈便宜。
