Claude Code 指南 4｜CLAUDE 檔：專案守則

在本單元中，會介紹 CLAUDE.md 這個檔案是什麼、放在哪一層各代表什麼範圍、該寫什麼不該寫什麼，以及一份可以直接改用的編輯室守則範例。

一句話：這是這個資料夾的員工手冊

CLAUDE.md 就是放在你專案資料夾裡的一個純文字檔。你每次在這個資料夾開啟對話，它的內容會自動被讀進去，不用你提醒、不用你貼。

換成單位的語言：這是你單位的員工手冊。新人第一天要交代的那些事，寫進去就不必每次口頭講一遍。

什麼時候該往裡面加一條

四個時機，任何一個出現就代表這條該寫下來：

  • 同一個錯它犯第二次
  • 你這個對話打的糾正，上個對話也打過
  • 新來的同事需要同一段背景才做得對
  • 你發現自己在解釋「我們這裡的做法是」

判斷標準是：這件事是不是每次開對話都成立的事實或規矩。 是，寫進 CLAUDE 檔；只在某一類任務才用到的多步驟程序，那是 skill 的事，見指南 6。

放哪一層，決定誰受它管

範圍 位置 適合放什麼 誰會受影響
機構層 由資訊單位部署到系統目錄 全機構的合規與安全原則 機構裡每一台機器
你個人 ~/.claude/CLAUDE.md 你自己的偏好，跨所有專案 只有你，但在你所有專案都生效
專案 專案資料夾裡的 CLAUDE.md 這個專案的規矩，可以給團隊共用 開這個資料夾的所有人
個人加在專案上 專案資料夾裡的 CLAUDE.local.md 你自己在這個專案的偏好，不想給別人看到的 只有你

從你的工作資料夾往上，每一層的 CLAUDE 檔都會被讀進來，而且是相加不是覆蓋。越靠近你啟動位置的，越後被讀到。

實務上你只需要記兩個：綁專案的寫在專案資料夾的 CLAUDE.md，綁你自己的寫在 ~/.claude/CLAUDE.md。

怎麼建起來

做法 怎麼做
最省事 在對話裡打 /init。它看一遍你的資料夾，草擬一份給你，你再改。已經有檔案的話它提建議，不會覆蓋你寫的
最直接 在資料夾裡新增一個叫 CLAUDE.md 的檔案，把規矩打進去。名字必須完全一樣，全大寫
確認有被讀到 打 /context，看 Memory files 那一區有沒有列出你的檔。沒列出來就是它沒看到

/memory 可以直接把這些檔叫出來編輯，不用自己去資料夾裡找。

一條規則要具體到可以驗證，否則等於沒寫

沒用的寫法 有用的寫法
公文要寫得正式 公文一律用「主旨、說明、辦法」三段，主旨一句話講完
注意用字 不要用「爰此」開頭，改用「有關」或直接切入事由
小心處理已發布的內容 不可更動 已發布/ 資料夾內的任何檔案

判斷法：這一條，第三個人讀了能不能判斷你有沒有照做？不能，就再寫具體一點。

超過兩百行，遵守度會開始掉

這份檔每次對話都會佔掉 context，寫太長不但花錢，它照做的比例還會下降。太長就把用不到每次的部分搬去 skill。

不要寫它讀檔案就知道的事

資料夾裡有什麼、檔名怎麼取，它自己讀得到，寫進去只是浪費空間。要寫的是讀檔案讀不出來的東西：慣例、禁區、為什麼這樣做。

兩條規則打架的時候，它會挑一條，你控制不了挑哪一條

所以每隔一段時間要回頭看一次，刪掉過時的、合併重複的。守則跟員工手冊一樣會長出互相矛盾的條文，差別只在沒有人會來抱怨。

一份可以直接改用的編輯室守則

把下面這段存成專案資料夾裡的 CLAUDE.md，把方括號的部分換成你單位的真實規矩：

# 〔部門名稱〕AI 使用守則

## 這個資料夾在做什麼
這裡放〔部門〕的新聞稿、公告與逐字稿。原始素材在 `素材/`，
成品在 `成品/`，已經對外發布的在 `已發布/`。

## 絕對不可以做的事
- 不可更動 `已發布/` 底下的任何檔案
- 不可把 `素材/` 裡含受訪者個資的檔案內容複製到別的檔案
- 不可自行編造數字、日期、職稱、法條；查不到就標〔待確認〕

## 寫作慣例
- 一律使用台灣繁體中文與台灣慣用詞
- 數字用阿拉伯數字，年份用西元
- 不使用破折號插入語，改用逗號或括號
- 新聞稿採倒金字塔結構，第一段講完人事時地物

## 每次產出都要附的東西
- 產出文稿時，最後附一張查證清單，列出文中每個數字、日期、
  金額、法條、人名職稱，並標出哪些還沒有來源

## 需要先問我的動作
- 刪除任何檔案
- 一次改動三個以上的檔案
- 把內容寫進 `成品/` 以外的資料夾

最後那一段值得特別講：你可以用守則要求它在做某些動作前先問你。 不過守則是「脈絡」不是「強制設定」，它會照著做，但沒有百分之百的保證。真正要擋死某個動作，要用 hook 這種機制，或者把權限模式維持在 Manual。這個差別在治理上很重要：守則塑造行為，設定才是強制執行。

帶回你的編輯室

  • 你單位的員工手冊，寫得出一份 CLAUDE 檔嗎？寫不出來，是手冊不清楚，還是規矩本身就沒講清楚？
  • 全機構共用一份守則，跟各部門各有一份，差別在哪？哪些條目非得放在最上層？
  • 「不可動已發布資料夾」這種條目，在你單位對應的是什麼？把它寫出來。

檢查清單

  • [ ] 你的專案資料夾裡有一個 CLAUDE.md
  • [ ] /context 看得到它被載入
  • [ ] 裡面每一條都具體到可以驗證，不是「注意品質」這種話
  • [ ] 有一條禁區、一條格式、一條需要先問你的動作
  • [ ] 總長度沒有超過兩百行
