Acceptance Criteria｜驗收條件（Acceptance Criteria, AC）

一條需求要滿足哪些具體條件，才算做完——由產品端寫，工程端照著驗。

這個詞在說什麼

驗收條件把「做好了沒」從感覺變成可以查的事實。寫法通常是清單或 Given / When / Then：在什麼前提下、做了什麼動作、應該看到什麼結果。

它是 PRD 與 user story 的收口。沒有驗收條件的需求，最後會由工程師自己決定什麼叫完成，而你在驗收會議上才發現彼此想的不一樣。

常見誤解

  • 把驗收條件寫成功能描述的複述。條件要能判真假，「介面要好用」不能判真假。
  • 只寫成功情境。錯誤輸入、權限不足、網路斷掉那幾條，才是上線後真的會發生的。
