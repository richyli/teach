Claude Code 指南 3｜介面、權限模式與第一個指令

在本單元中，會介紹面板上每個東西是做什麼的、四種權限模式差在哪、三段式指令怎麼寫，以及怎麼用一段你自己的真實工作跑完第一輪並驗收。

面板上你只要認得五樣東西

打開 Claude 面板，由下往上看：

位置 是什麼 你什麼時候會動它
輸入框 你打字的地方 一直
輸入框下方的模式字樣 目前的權限模式 每次任務開始前確認一次
模式旁邊的模型名稱 現在用哪個模型 換複雜任務時
輸入框上方的用量指示 這一輪用掉多少 context 對話變長時
面板頂端的歷史紀錄 過去的對話 要接續昨天的工作時

在輸入框打一個 / 會叫出命令選單，裡面有附加檔案、切換模型、管理 MCP、設定記憶等等。指令不用背，打 / 找就好。

四種權限模式，決定它做事前要不要問你

這是整套工具裡唯一跟「風險」直接相關的設定。點輸入框下方的模式字樣可以切換。

模式 行為 什麼時候用
Manual（手動） 改檔案、跑指令前都問你 第一週，以及任何動到真實檔案的任務
Plan（計畫） 只規劃不執行，先給你一份計畫等你批准 大範圍改動之前，例如整批改檔
Edit automatically（自動編輯） 檔案編輯不問，其他仍問 你已經跑熟、而且動的是副本
Auto（自動） 多數動作由分類器檢查，不逐一問你 熟悉之後的日常任務

還有一個 bypass 模式是全部都不問，第一個月不要碰它。那個模式的用途是無人值守的排程作業，不是給你省事用的。

在 Plan 模式下，VS Code 會把計畫當成一份完整文件打開，你可以在上面加註解再讓它開始。要改一整批檔案時，先用 Plan 看它打算怎麼動，比事後補救便宜得多。

驗收有三個介面，不要只看最後結果

第一個是它的計畫。 動手之前它會先說要做什麼。這段常常就看得出它誤會了你的意思，這時喊停最便宜。

第二個是並排比對。 它要改檔案時，左邊是原文、右邊是改動後，你可以直接在比對畫面上手動改，再按接受。你動過之後它會知道成品跟它的提案不同。

第三個是確認鍵。 那個要你按 Allow 或 Deny 的提示，就是人類的煞車。一路按 yes 等於把煞車拆了。

一句話：你負責下指令跟驗收，它負責執行。

第一個指令，挑一個不會壞事的

在面板打這一句，按 Enter：

請用一句話說明我現在這個資料夾裡有什麼。不要修改任何檔案。

你會注意到三件事：它先講它打算怎麼做；它會問你要不要授權它讀檔；同一句話不同人跑出來的結果不一樣。第三件事是接下來整段的重點。

三段式：背景、任務、格式

好結果來自把話講死。一個能用的指令有三段：

段 你要交代什麼 常見的漏法
背景 你是誰、幫誰做、這是什麼文件 最常漏這段，它只好自己想像你是誰
任務 要達成什麼、有哪些要件、分幾步 只寫「整理一下」，結果一定發散
格式 輸出長什麼樣、多長、給誰看 沒講就給你一大坨

每留白一處，它就替你自作主張一處。

一個可以直接改用的樣板：

背景：我是一家電視台的新聞部主管，這是我昨天訪談某位受訪者的逐字稿。

任務：幫我抓出三個主要論點，每個論點配一句逐字稿原文當佐證，並標出哪一段我引用前需要再回去確認。

格式：條列，每點不超過兩行，最後附一張表列出需要確認的段落。

結果不夠好的時候，先問自己改哪一段，而不是換一個模型。多數人第一次都是漏了背景，或沒講格式。

帶檔案進來的兩種方法

方法 怎麼做 什麼時候用
@ 帶檔 在輸入框打 @ 接檔名，它會模糊比對，打一部分就找得到。資料夾在名稱後加斜線，例如 @逐字稿/ 要它處理一整份檔或一整個資料夾
反白選取 在編輯器裡反白一段文字，輸入框下方會顯示選了幾行。按 Alt+K（Mac 是 Option+K）可以把「這個檔的第幾行到第幾行」插進提示裡 只要它看某一段，不要它讀整份

大份的 PDF 可以叫它只讀特定頁數，例如「只讀第 3 到第 10 頁」，比整份丟進去省得多。

對話變長之後會發生什麼事

它這一輪看得到的所有文字統稱 context，有上限。塞得越滿，回應越慢、越貴，判斷也越容易散掉。

兩個處理方式：

  • /compact：叫它把目前的對話自己摘要成精簡版，帶著摘要繼續。簡單的任務夠用。
  • 手動交棒：叫它寫一份「下一個對話的接手指南」，內容是什麼做完了、卡在哪、下一步做什麼，存成一個檔。然後開新對話，第一句叫它讀那份檔。複雜任務一律用這一招，/compact 會漏掉關鍵細節。

另外，一個任務開一個新對話。不要在同一串對話裡先寫新聞稿再做法規比對，前面的內容會污染後面的判斷。

模型跟思考深度，從便宜的開始

打 /model 會列出目前可用的模型，通常分成三個級距：最強的適合複雜推理與長文寫作，中階的適合日常九成任務，輕量的適合短問答與格式轉換。同一個選單裡通常還能調思考深度（effort）。

選法很簡單：先用中階跑，跑壞了再換強的重做一次，通常比一開始就用最強的省。寫提案、設計 skill 這類需要判斷的事再往上調。

不要記版本號，改版很快，看選單當下列了什麼就選什麼。

動手：用你自己的一段真實工作跑一次

這一節做完，W3 的小作業就有東西交了。

材料用你手上真的在處理的東西：一份訪談逐字稿、一份要彙整的報告、一封要回的長信都可以。手邊沒有的話，去你的信箱找一封這週最長的工作信，把內文貼進一個文字檔存起來，那就是材料。

  1. 放料：把那份檔案複製進你開啟的那個資料夾，確認左側清單看得到它。
  2. 確認模式：把權限模式切到 Manual。
  3. 下指令：用上面的三段式樣板改寫成你自己的版本，用 @ 帶入那個檔。
  4. 先讀計畫再放行：它會先說它打算怎麼做，讀完再按允許。
  5. 看它動檔案：如果它要改檔，在並排比對畫面上一處一處看，不確定的按拒絕並告訴它為什麼。
  6. 立刻標記：結果出來，馬上寫下「它對的一處」與「它錯的一處」。過五分鐘你就想不起來了。
  7. 改一次提示再跑一次：把你剛剛發現的不足補進三段式，重跑。比較兩次的差別。

要交的東西有三樣：對的一處、錯的一處、一句「下次我會怎麼改提示」。

大家第一次最常犯的四件事

錯誤 會發生什麼 怎麼修
開錯資料夾 它說找不到檔案 重新用「開啟資料夾」開對位置
指令太籠統 結果發散、不能用 回去補背景與格式，把任務拆成編號步驟
一路按 yes 它改了你不想動的檔 切回 Manual，逐處看比對畫面
期待一次到位 覺得這工具不過如此 好結果是問三到五次問出來的，不是一次寫對

檢查清單

  • [ ] 你認得面板上的模式字樣，而且知道現在是哪個模式
  • [ ] 你跑過一個不會改檔的暖身指令
  • [ ] 你用三段式寫過一個指令，三段都有內容
  • [ ] 你讀過它的計畫才放行，不是直接按到底
  • [ ] 你手上有「對的一處」與「錯的一處」可以交作業
