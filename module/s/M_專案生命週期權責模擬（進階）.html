M 專案生命週期權責模擬（進階）

90 分鐘進階模擬（practice，佔 2 個 45′ slot，可拆兩週）。跨課共用（Product / EMA）。先修：M 決策權與權責分配框架、M 權責角色辨識與職權糾錯演練。概念依據：權責框架的情境適配、分工與權責框架全景。

為什麼要學（動機）

前兩個演練都在靜態的一張表上練功。但真實專案會長大、轉型、出事、換人——上週剛好的分工，下週就崩了。這場模擬把同一個專案推過完整生命週期（探索 → 專案 → 跨組織營運 → 危機），每一關的類型、規模、時長都不同，逼你一再重排權責、整合全部框架，並在最後看清一件事：最貴的錯不是排錯，是該重排時沒重排。

學習目標（能力 → 能解釋的真實問題）

  • 應用×分析：能依專案的類型／規模／時長選出並組裝合適的框架組合包 → 能回答「這個階段到底該用輕 DRI 還是全套 RACI＋三道防線」。
  • 評鑑：能判斷「隨專案演進，哪個角色的職權該變而沒變」的隱形風險 → 能回答「為什麼上線後那個一直沒改的分工把我們害慘了」。
  • 創造：能設計一條跨階段的角色演變路徑與交接／升級機制 → 能回答「當專案從三人變三十人、從試做變常態，我的權責結構怎麼跟著長」。

課前／起手式：與 AI 對話（先探索動態感再進課堂）

上課前跑任一方向，帶著產出與疑問進來：

  • 規模三連跳：「請描述同一個新創產品在 3 人／30 人／300 人三種規模下，權責分工該怎麼不同。」你來判斷它有沒有守住「框架重量與規模相稱」。
  • 快轉未來：把你的期末專案給 AI，請它模擬「三個月後專案爆紅／出事」的情境，你來想那時哪個角色該重排、哪個該變卻可能沒變。
  • 跟難搞的人談判：請 AI 扮一個「想掛名共同發布、卻不想扛錯的當責」的利害關係人跟你談，你練習怎麼把當責釘回去。

模擬設定

專案（預設；亦可換各組期末專案）：一家區域新聞媒體要推出「AI 輔助的地方選舉即時查核平台」——週末原型 → 正式產品 → 與外部事實查核聯盟跨組織合作 → 選舉日常態營運與危機。

分組：5–6 人一組。每人抽一張角色卡（含私下目標），全程扮同一角色；私下目標會自然製造職權衝突，正是觀察重點。

教師是「遊戲主持人（GM）」，每回合開場宣讀情境、中途丟一張 curveball 注入卡（inject），回合末各組交產出。四回合 + 復盤。

回合流程（4 回合）

回合一　探索：週末原型（類型=探索／規模=2–3 人／時長=週末）~15′

  • 任務：用最輕的分工把原型做出來，決策要快、可逆（Type 2）。
  • 注入（中途）：原型意外爆紅、被同業報導 → 「要不要正式立項？」
  • 產出：指定一個 DRI；說明「立項與否」用什麼最小決策機制（advice process／consent）。
  • 診斷重點：有沒有人過度套上完整 RACI？探索期套重框架＝自綁手腳。

回合二　立項：正式跨部門專案（類型=專案／規模=跨團隊／時長=一季）~20′

  • 任務：立項後跨部門（工程／編輯／法務／資訊）。畫分階段 RACI＋用 RAPID decision framework／DACI decision framework 處理「上線範圍」這個重大決策；把法務正式納入 Agree、指定唯一 Approver／Decide。
  • 注入：選舉委員會來函關切 → 這個決策從 Type 2 變 Type 1（不可逆、高敏感）。
  • 產出：跨部門 RACI＋一張 RAPID 決策表＋一句話說明「為何要升級 ceremony」。
  • 診斷重點：決策類型改變時，框架重量有沒有跟著升？還是沿用原型期的隨便決？

回合三　規模化：跨組織營運（類型=平台／規模=跨公司／時長=選前常態）~20′

  • 任務：與外部事實查核聯盟、社群平台合作。決策權跨組織 → 需合約化的 Agree、聯合治理；「發布查核結果」流程加 職務分離／maker-checker（避免單一人誤標）；角色改綁職位不綁人。
  • 注入：核心工程主管離職 → 當責如何交接？「角色綁人」的風險現形。
  • 產出：跨組織決策治理草圖＋一個職務分離控制點＋一份當責交接方案。
  • 診斷重點：規模跳到跨組織後，還想用小團隊的「一人 DRI 到底」嗎？有沒有把當責綁在會離職的「人」身上？

回合四　危機：選舉日事件（類型=危機／時長=數小時）~15′

  • 注入（開場即爆）：選舉日，平台把一則真消息誤標為假、瘋傳，各方究責湧入。
  • 任務：切換到危機模式——ICS 式單一 Incident Commander、集權快決（Type 1 speed，Vroom AI／AII）、明訂誰對外交代、其餘人 disagree-and-commit。事後標出誰當責。
  • 產出：危機角色配置（Commander／對外發言／技術止血／法務）＋一句「平時分權 ≠ 危機分權」的具體對照。
  • 診斷重點：平時的分散授權，在危機中有沒有及時收斂成單一指揮？還是繼續開會共識決、貽誤止血？

收尾　跨回合復盤（~15′，全模擬的靈魂）

  1. 畫角色演變圖：每組挑 2 個角色（建議法務、工程主管），畫出它在四回合的職權如何變化。例如法務：R1 缺席 → R2 Agree（會簽）→ R3 跨組織合約否決 → R4 危機顧問。
  2. 一起收斂一題：把各組的演變圖攤開，回答核心問題——「哪一個角色的職權『該變卻沒變』，最可能把專案害慘？」（對照 權責框架的情境適配 的動態原則）。
  3. 個人反思：「我的期末專案現在在哪個階段？下一個階段一到，我第一個要重排的角色是＿＿＿，因為＿＿＿。」

小作業

為你的期末專案畫一張「權責演變路線圖」：至少切 3 個階段（如試做／上線／營運），每階段標明框架組合（用哪些）、唯一當責者、以及跨階段的交接或升級觸發條件（什麼事件一發生就該重排）。評分看：三軸判斷是否合理、動態重排是否到位、每階段是否都有唯一當責。

角色卡與私下目標（製造衝突的引擎）

角色 公開目標 私下目標（會誘發的職權錯誤）
總編輯／發行人 平台成為招牌、衝影響力 想搶選舉檔期快上線，傾向壓過法務（誘發：越級決策、忽略 Agree）
工程主管 準時交付、技術 KPI 想被全權授權、討厭被 review 拖慢（誘發：R 自行拍板；R3 離職伏筆）
法務／法遵 零選舉法／版權風險 傾向對所有事行使否決（誘發：否決權越權）
外部事實查核夥伴 聯盟能見度 想掛名共同發布但不想扛錯標的責任（誘發：當責真空）
資訊部／資安 系統穩、資安過關 「沒過我這關不能上內網」但常被略過（誘發：隱形否決權）
贊助方／廣告主 品牌能見度、ROI 想介入決策但不想負責（誘發：有權無責）

注入卡時間軸（GM 中途丟出）

  • R1：原型爆紅 → 立項壓力（測「探索期會不會過度上框架」）
  • R2：選委會來函 → 決策升 Type 1（測「類型變、ceremony 跟不跟」）
  • R3：工程主管離職 → 當責交接（測「角色綁人 vs 綁職位」）
  • R4：誤標真消息瘋傳 → 危機（測「平時分權能否收斂成單一指揮」）

復盤解答重點（各回合「應然」框架組合）

  • R1 → DRI＋advice/consent；忌完整 RACI。
  • R2 → 分階段 RACI＋RAPID／DACI；法務入 Agree、唯一 Approver；Type 1 升級 ceremony。
  • R3 → 合約化 Agree＋聯合治理＋職務分離（maker-checker）＋角色綁職位＋交接方案。
  • R4 → ICS 單一 Incident Commander＋集權快決＋明訂對外當責＋disagree-and-commit。
  • 共通致命傷：該重排卻沿用上一階段的分工（把小框架硬套到大規模、平時分權硬撐到危機）。
