Claude Code 指南 7｜MCP：接上外部資料

在本單元中，會介紹 MCP 是什麼、用網頁點一次就能接上的那條路怎麼走、用指令接的寫法，以及台灣場景可以接什麼。最後一節講每接一個就同時擴大了什麼風險。

沒有 MCP，它就被關在你的資料夾裡

預設狀態下，它只看得到你啟動時所在的那個資料夾。你真正的工作卻散在別的地方：行事曆、試算表、CRM、政府資料庫、內部系統。

MCP（Model Context Protocol）是讓 AI 跟外部服務對話的通用標準，2024 年由 Anthropic 提出，現在其他家也在用。把它想成轉接頭：插上去之前，它伸手碰不到你資料夾以外的世界；插上去之後，它自己去拿。

差別很具體：

料從哪來 你要做什麼
沒有 MCP 只有你的資料夾 每次自己把試算表複製貼上
接上 MCP 試算表、行事曆、開放資料 喊一聲，它自己去讀

沒接資料源的 skill，再漂亮也只是一個純文字模板。這是指南 6 那些 skill 的天花板，MCP 是把天花板打開的東西。

最快的一條路：在網頁點一次

行事曆、雲端硬碟、信箱這類服務，走 claude.ai 的 Connectors 最快，不用裝任何東西，也不用打任何指令。

  1. 開 <https://claude.ai/customize/connectors>，用你跑 Claude Code 的同一個帳號登入。
  2. 找到你要的服務，點 Connect。
  3. 跳出該服務的授權頁，選帳號、同意權限，跳回來之後狀態變成已連接。
  4. 回到 VS Code 的 Claude 面板，直接用講的：「幫我看下週的行事曆。」

它會自己判斷要呼叫哪個工具、跳出確認、你按下去就跑。你描述的是意圖不是步驟，這就是 agentic 的感覺。

兩個要注意的地方：網頁跟 Claude Code 必須是同一個帳號，否則抓不到；Team 與 Enterprise 方案通常只有管理員能新增。

用指令接：claude mcp add

不在 Connectors 清單上的服務，用指令接。在終端機打（不是在對話框裡）：

claude mcp add --transport http <名稱> <網址>

例如：

claude mcp add --transport http notion [https://mcp.notion.com/mcp](https://mcp.notion.com/mcp)

需要帶金鑰的服務，多一個 header：

claude mcp add --transport http <名稱> <網址> --header "Authorization: Bearer 你的token"

有些服務不是網址而是跑在你電腦上的程式，那種要用 -- 把後面的指令隔開：

claude mcp add --transport stdio <名稱> -- npx -y <套件名稱>

這些指令你不用背。要接什麼服務，把它的官方說明頁貼給 Claude Code，叫它幫你接。 它會判斷該用哪一種，該打什麼。

接完之後，在對話框打 /mcp 會列出所有伺服器與狀態。要登入的服務在這裡完成授權；顯示失敗的也在這裡重試。VS Code 的面板裡打 /mcp 同樣可以新增、移除、管理。

接了之後誰用得到

範圍 指令 誰用得到
只有這個專案（預設） 不用加 你，而且只在這個專案
專案共用 --scope project 設定寫進專案的 .mcp.json，團隊共用
你所有專案 --scope user 你，在所有專案

團隊共用那一種會在資料夾裡生出一個 .mcp.json，可以跟著版本控制走。第一次打開別人專案時，它會先問你要不要批准那些伺服器，不要無腦批准。

台灣場景可以接什麼

國外的 MCP 多半解美國或全球的問題。台灣本地的查詢有一個集合叫 Twinkle MCP（<https://hub.twinkleai.tw/>），把政府開放資料、政府電子採購網、立法院資料包成 MCP。接上之後，下面這些都是直接用講的：

  • 「查某機關 2026 年以後的決標公告，按金額排序列前二十件」
  • 「用統編查這家公司的登記資料、董監事、分公司」
  • 「查第 11 屆立法院關於某個法案的議案與表決紀錄」
  • 「查某個路段 2024 年以後的實價登錄成交紀錄」

對媒體來說，這幾類查詢分別對應到標案調查、廠商背景查核、法案追蹤、地產線的即時查證。過去要開四個網站慢慢翻，現在是一句話。查到的東西仍然要回原始資料核對一次，理由在下一節。

每接一條線，都同時擴大了兩件事

這是這一份最重要的一段。

接上一個資料源，等於同時擴大了它能做的事、跟它能做錯的事。新增一個連接器不是技術上的方便而已，是一個決策：你決定了它現在可以碰什麼。

三個要一起想的風險：

第一，它會把不存在的東西講得很篤定。接了法規資料庫不代表它引的條號一定對。它的角色是幫你快速定位該看哪幾條，不是替你做成決定。凡是要引為依據的，一律回原文核。

第二，讀外部內容的伺服器帶進提示注入風險。它去讀了一個網頁，網頁裡藏著寫給 AI 看的指令，它可能就照做了。所以連接前要確認你信任那個服務，以及那個服務會讀到什麼內容。

第三，權限是雙向的。接上信箱代表它讀得到信；接上雲端硬碟代表它讀得到檔。你單位的哪些資料可以讓它碰，這是編輯政策與資安政策，不是設定畫面上的一個開關。

實務上的起手式：先接唯讀的、先接公開資料的、先接不痛的。行事曆跟政府開放資料是好的第一條線；內部人事系統不是。

帶回你的編輯室

  • 盤點一下：你單位現在用的雲端工具（CRM、ERP、HR、會計、雲端硬碟），哪些已經有 MCP 可以接？哪些還沒有？
  • 沒有 MCP 的服務，你會考慮換掉，還是請資訊單位自己搭一個？
  • 反過來想：你的機構對外提供得了 MCP 嗎？如果讀者或客戶的 AI 想直接讀你的內容目錄、查你的帳戶狀態，你準備好了嗎？
  • 這跟當年「要不要做 API」「要不要做 App」是同一類問題嗎？窗口期會多長？

檢查清單

  • [ ] 你知道不接 MCP 它只看得到你的資料夾
  • [ ] 你至少接過一個服務，並在 /mcp 看到它顯示已連接
  • [ ] 你用講的叫它去那個服務拿過一次料
  • [ ] 你講得出這條線讓它多能做什麼、以及多能做錯什麼
  • [ ] 你沒有把含機密或個資的系統當成第一條線
