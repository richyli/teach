練習 16 - 月底廣告營收下滑

在本單元中，會介紹第 16 題「10 月下旬廣告營收一路往下掉，業務主管要你在會前說清楚是不是出事了」從頭到尾實際跑一次的方法、跑出來的數字，以及畫出來的圖。

這一頁是做完之後對答案用的。還沒動手的話，先回 Hub - 資料分析練習案例庫 找到這一題，照「怎麼做」那一欄自己跑一次再回來。

題目

有人會這樣問你：這個月廣告收入從 10 月 23 日以後一路往下掉，月底只剩高峰的四分之一。是市場冷掉了，還是我們自己出了什麼問題？
難度 入門
組別 第 6 組：時間、存活與回頭看的陷阱
用哪張表 ad_daily（L1 的 ad_daily_2024_10.csv）
對應單元 時間序列 明天的流量會怎樣

方法

先看 currency 欄，把記成 USD 的列乘 31.5 換成台幣，再依 stat_date 加總成 31 天的日營收序列；同一天再算兩個東西：當天在跑的活動數（campaign_id 去重計數）與總曝光數，然後算每千次曝光營收（台幣營收 ÷ 曝光數 × 1000）。三條線畫在一起看。用 Python 的理由：853 列資料用 pandas 的 groupby 三行就變成日序列，算完直接畫圖，不必把資料搬到別的工具。

程式

這一題用 Python，整支程式如下。資料放在 dist/L1 與 dist/L2 兩個資料夾。

from _kmg import *

r = R(16, "10 月下旬廣告營收一路往下掉，業務主管要你在會前說清楚是不是出事了")
a = ad()
a["twd"] = twd(a)
r.chk("換算後全月營收", 2975076, round(float(a["twd"].sum())), tol=2)
r.chk("直接加總", 1947799, round(float(a["revenue"].sum())), tol=2)

d = a.groupby("stat_date").agg(rev=("twd", "sum"), raw=("revenue", "sum"),
                               camps=("campaign_id", "nunique"), imp=("impression_cnt", "sum"))
d["ecpm"] = d["rev"] / d["imp"] * 1000

def day(n):
    return pd.Timestamp("2024-10-%02d" % n)

r.chk("10/1 日營收（萬）", 1.3, d.loc[day(1), "rev"] / 1e4, tol=0.06)
r.chk("10/23 日營收（萬）", 18.6, d.loc[day(23), "rev"] / 1e4, tol=0.06)
r.chk("10/31 日營收（萬）", 4.8, d.loc[day(31), "rev"] / 1e4, tol=0.06)
r.chk("營收高點在 10/23", True, bool(d["rev"].idxmax() == day(23)))
r.chk("10/1 在跑的活動數", 2, int(d.loc[day(1), "camps"]))
r.chk("在跑活動數高點", 30, int(d["camps"].max()))
r.chk("10/31 在跑的活動數", 10, int(d.loc[day(31), "camps"]))
r.chk("每千次曝光營收 最低", 50, float(d["ecpm"].min()), tol=1)
r.chk("每千次曝光營收 最高", 116, float(d["ecpm"].max()), tol=1)
slope = float(np.polyfit(np.arange(len(d)), d["ecpm"].values, 1)[0])
r.chk("每千次曝光營收沒有走低（日斜率 ≥ -0.5 元）", True, slope >= -0.5)
r.note("每千次曝光營收的日斜率 %.2f 元／天，一個月下來不到 15 元，相對於 50 到 116 元的日間震盪看不出趨勢" % slope)

first = a.groupby("platform")["stat_date"].min()
r.chk("10/1–10/2 只有程序化平台在投", True,
      bool(a.loc[a["stat_date"] <= day(2), "platform"].isin(["openx_prog", "adx_prog"]).all()))
r.chk("自助平台進場日", "2024-10-03", str(first["kmg_selfserve"].date()))
r.chk("直客平台進場日", "2024-10-04", str(first["kmg_direct"].date()))
r.chk("10/1 未換算營收（元）", 406, float(d.loc[day(1), "raw"]), tol=1)
r.chk("10/2 未換算營收（元）", 1528, float(d.loc[day(2), "raw"]), tol=1)
g_raw = float(d.loc[day(7), "raw"] / d.loc[day(1), "raw"])
g_conv = float(d.loc[day(7), "rev"] / d.loc[day(1), "rev"])
r.chk("10/1 到 10/7 未換算漲幾倍", 100, g_raw, tol=2)
r.chk("10/1 到 10/7 換算後漲幾倍", 6.5, g_conv, tol=0.05)
r.chk("10/3 未換算 比前一天（倍）", 1.6, float(d.loc[day(3), "raw"] / d.loc[day(2), "raw"]), tol=0.05)
r.chk("10/3 換算後 比前一天（倍）", 0.26, float(d.loc[day(3), "rev"] / d.loc[day(2), "rev"]), tol=0.005)
r.chk("10/4 未換算 比前一天（倍）", 4.8, float(d.loc[day(4), "raw"] / d.loc[day(3), "raw"]), tol=0.05)
r.chk("10/4 換算後 比前一天（倍）", 1.7, float(d.loc[day(4), "rev"] / d.loc[day(3), "rev"]), tol=0.05)

r.pit(g_raw > 50 and g_conv < 10, "月初第一週，沒換算的日營收漲了 %.0f 倍，換算後只漲 %.1f 倍" % (g_raw, g_conv))
by_cur = a.groupby(["stat_date", "currency"])["twd"].sum().unstack(fill_value=0)
flip = (d.loc[day(3), "raw"] > d.loc[day(2), "raw"]) and (d.loc[day(3), "rev"] < d.loc[day(2), "rev"])
r.sc(bool(np.allclose(by_cur.sum(axis=1).values, d["rev"].values)) and flip,
     "兩種幣別分開畫再相加，剛好等於總營收線；10/3 沒換算是上漲、換算後是下跌，方向都相反")

fig, ax = plt.subplots(4, 1, figsize=(8, 9), sharex=True)
ax[0].plot(d.index, d["raw"] / 1e4, color="#bbbbbb", label="沒換算，直接加總")
ax[0].plot(d.index, d["rev"] / 1e4, color="#4f81bd", label="換算成台幣")
ax[0].set_ylabel("日營收（萬元）")
ax[0].set_title("月初那段「起飛」大半是幣別造成的")
ax[0].legend()
ax[1].stackplot(by_cur.index, by_cur["TWD"] / 1e4, by_cur["USD"] / 1e4, labels=["台幣平台", "美金平台（已換算）"],
                colors=["#f79646", "#4f81bd"], alpha=0.8)
ax[1].set_ylabel("日營收（萬元）")
ax[1].legend(loc="upper left")
ax[2].plot(d.index, d["camps"], color="#9bbb59")
ax[2].set_ylabel("在跑的活動數")
ax[3].plot(d.index, d["ecpm"], color="#8064a2")
ax[3].set_ylabel("每千次曝光營收（元）")
ax[3].set_title("單價全月在 50 到 116 元之間震盪，沒有往下走")
fig.autofmt_xdate()
save_fig(fig, "ex16_timeseries.png")
r.save()

程式裡的 r.chk(項目, 預期值, 實算值) 是對照檢查，把入口頁寫的數字跟實際算出來的放在一起比；r.pit 記錄坑有沒有出現，r.sc 記錄自己驗那一步有沒有效。畫圖的部分在程式最後面。

程式開頭的 from _kmg import * 載入共用的讀檔、去重、換幣別與畫圖函式，內容在 練習 01 - 月會上的則數對不對 的「共用的讀檔函式」那一段。

結果

換算後全月營收約 297.5 萬元，直接加總只有 194.8 萬元，少掉大約三分之一。日營收從 10/1 的 1.3 萬元爬到 10/23 的 18.6 萬元，月底掉回 4.8 萬元；但同一天在跑的活動數也從 2 檔爬到 30 檔再掉到 10 檔。每千次曝光營收全月都在 50 到 116 元之間上下震盪、沒有走低的趨勢。所以營收的起落是跟著檔期走，不是單價崩掉。

這題的坑，實際跑的時候有沒有出現

幣別混用（KMG 埋的第二個陷阱）。10/1、10/2 只有兩個程序化平台在投，記的都是 USD，直接 sum(revenue) 會讓這兩天看起來只有幾百到一千多元；台幣平台 10/3（自助）、10/4（直客）陸續進場後，沒換算的序列從 10/1 到 10/7 一路漲了 100 倍，換算後其實只漲 6.5 倍。更誤導的是 10/3：沒換算看起來比前一天多 1.6 倍，換算後其實掉到前一天的四分之一。很多人會把月初這一段寫成「10 月初廣告起飛」，其實那是幣別造成的假趨勢，跟市場一點關係都沒有。

實際跑的結果：月初第一週，沒換算的日營收漲了 102 倍，換算後只漲 6.5 倍。

自己驗那一步抓不抓得到錯

把每天的營收依 currency 分成兩組各印一條線，兩條相加要剛好等於你的總營收線；接著比較「有換算」與「沒換算」兩個版本，如果月初那段「起飛」在沒換算的版本特別陡、換算後就平下來（例如 10/4 單日，沒換算跳 4.8 倍、換算後 1.7 倍），代表你抓到的是幣別不是市場。

實際跑的結果：兩種幣別分開畫再相加，剛好等於總營收線；10/3 沒換算是上漲、換算後是下跌，方向都相反。
