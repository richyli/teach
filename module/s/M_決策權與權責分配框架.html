決策權與權責分配框架

為什麼要學（動機）

團隊卡住，十次有九次不是「不會做」，而是沒人知道誰能拍板、事情做完卻沒人負責、或人人都有否決權於是永遠喬不定。AI 讓「做東西」變便宜，於是團隊瓶頸更明顯地移到「決策與協調」——這正是決策權（decision rights）與權責分配框架要解的問題。學會這套框架，你能把「一句話講不清楚的責任歸屬」變成一張人人看得懂的表。

學習目標（能力 → 能解釋的真實問題）

  • 記憶／理解：說得出 RACI、RAPID、DACI、DRI 四種框架各自的角色定義 → 能看懂一份專案文件裡「誰是 A、誰只是被 Informed」到底在講什麼。
  • 應用：能為一個真實任務畫出 RACI、為一個真實決策設計 RAPID/DACI → 能回答「這次 AI 工具要不要導入，到底該誰拍板、誰有否決權」。
  • 分析：能診斷一份權責表的病灶（多個 A、隱形否決權、責任真空） → 能解釋「為什麼上次那個決策拖了三週還喬不定」。
  • 評鑑：能判斷一個決策該用哪種框架、該花多少 ceremony（用 Type 1／Type 2 之分） → 能回答「這件事值得開三次會設 RAPID，還是指一個 DRI 三分鐘決掉就好」。

課前／起手式：與 AI 對話（先摸過一輪再進課堂）

上課前，把下面任一方向貼進 chatbot 跑一輪，把你的產出與冒出來的疑問帶進課堂當活動素材：

  • 要例子：「請舉三個我生活或（傳播／新聞／資管）科系裡『決策卡住，或出事後沒人扛』的真實例子，各判斷缺的是『負責（沒人做）』還是『當責（沒人交代）』。」
  • 先分再挑錯：把你正在做的一個團體專案丟給 AI，請它幫你初步分出 RACI 四角；你來挑它哪裡分錯（尤其有沒有給出兩個 A）。
  • 當對手：對 AI 主張「一件事可以有兩個人一起負全責」，請它扮魔鬼代言人反駁你，看你能不能守住。
  • 打比方：請 AI 用你熟悉的東西（球隊／家庭／社團）解釋 RAPID 的 Decide 為何只能一人。

核心

一句話抓住整個家族：這些框架都在回答「一件事情裡，誰扮演什麼角色」——差別在焦點是「任務執行」還是「決策拍板」，以及輕重程度。

1. 四種主力框架

框架 焦點 角色 「唯一」的那個角色 特色
RACI 任務／交付物執行權責 Responsible｜Accountable｜Consulted｜Informed Accountable 唯一 專案分工矩陣的通用語
RAPID（Bain） 重大決策的決策權 Recommend｜Agree｜Perform｜Input｜Decide Decide 唯一 明確處理否決權（Agree）
DACI（Atlassian） 群體決策怎麼做出來 Driver｜Approver｜Contributors｜Informed Approver 通常唯一 分離推流程 vs 拍板
DRI（Apple） 單一負責人 一個直接負責人 DRI 唯一 最輕量，任何顆粒度都能用

共同心臟＝單一當責：RACI 的 A、RAPID 的 D、DACI 的 Approver、DRI 本身，講的都是同一件事——一件事只能有一個人最終負責。多個就是沒有。

兩個最常被混淆的區分： - Responsible vs Accountable（做事 vs 扛責）：可以同一人，也可以分開；但扛責的永遠唯一。 - Consulted vs Informed（雙向諮詢 vs 單向告知）：C 是「決定前問你意見」，I 是「決定後通知你」。把該 C 的人只當 I，就是把人得罪光的最快方式。

2. 常見變體（知道即可）

  • RASCI：RACI 加 S — Support（支援者），區分「主責」與「協助」。
  • CAIRO / RACIO：RACI 加 O — Omitted / Out-of-loop，明確標「這件事跟你無關」，反而減少雜訊。

3. 每個框架的典型踩雷（trap）

  • RACI：一列出現多個 A（等於沒人負責）；把該 Consulted 的人只放 Informed。
  • RAPID：出現多個 Decide；Agree（否決權）發太多張，變成人人能擋、事事卡關。
  • DACI：Driver 被當成 Approver（推討論的人自以為能拍板，或大家都以為他會拍板）。
  • DRI：一件事指不出單一 DRI——通常代表任務沒切乾淨或責任真的懸空。

4. 先決定「這個決策值多少 ceremony」——Type 1 / Type 2

不是每個決策都值得開會設 RAPID。先用 Bezos 的兩扇門分類：

  • Type 1（單向門，one-way door）：不可逆、代價高（如簽長約、砍產品線）→ 值得動用 RAPID／DACI 的完整流程與 Agree 否決關卡。
  • Type 2（雙向門，two-way door）：可逆、輸得起（大多數日常決策）→ 別過度設計，指一個 DRI 快速決掉，錯了再改。

決策做出後，用 Amazon 的 「disagree and commit（不同意但執行）」：反對意見在拍板前充分表達，一旦 Decide/Approver 拍板，全員承諾執行，不在事後反覆翻案——這是讓框架真正跑得動的文化配套。

5. 怎麼選？（決策樹）

  1. 只是要有人負責一件小事 → DRI。
  2. 要把整個專案的任務分工講清楚 → RACI。
  3. 要做一個牽涉多方、有人握否決權的重大決策 → RAPID。
  4. 要推動一個群體決策、且怕沒人推流程 → DACI。

演練｜為「AI 工具導入」設計決策權

情境（可換成各組自己的專案；預設媒體情境給 EMA）：你的編輯室要決定「是否導入某 AI 生成工具來產製新聞配圖」，導入後由美編團隊實際使用。

分組（4–5 人），20 分鐘內產出四樣東西：

  1. RACI（任務層）：把導入後的工作流拆成 3–5 個任務（如「產圖／事實查核／揭露標註／上稿」），畫一張 RACI，每列只能有一個 A。
  2. RAPID 或 DACI（決策層）：為「要不要導入」這個決策本身設角色——誰是 Decide／Approver？誰握 Agree（否決權）（法務？總編？）？誰只是提供 Input／Contributors？
  3. Type 分類：這是 Type 1 還是 Type 2 決策？據此說明你們花的 ceremony 是否相稱。
  4. DRI：指定導入專案的唯一 DRI。

跨組挑戰（openly）：相鄰兩組交換上述四份，互相找碴—— - 「你們的 A／Decide 是不是超過一人？」 - 「誰其實握有隱形否決權（例如資安、法務、平台方），卻沒被列進 Agree？」 - 「有沒有該 Consulted 的關鍵人只被你們放進 Informed？」

💬 討論／分享／反思

  • 一起收斂一題：各組交出「最容易被漏掉的隱形否決權角色」，全班投票選出媒體／產品情境中最常被忘記、卻能一句話讓整個導入喊卡的那個利害關係人（呼應 利害關係人與行動者網絡 的非人類 actant）。
  • 寫下個人反思：每人一句——「我過去在＿＿＿這件事上，其實從來沒搞清楚誰是 A；下次我會先問的一句話是＿＿＿。」

小作業

繳交你所屬期末專案的 一張 RACI + 一個重大決策的 RAPID/DACI 角色表，並標註：(1) 每個「唯一當責」角色是誰、(2) 至少一個你原本忽略的 Agree／Consulted 對象、(3) 這個決策是 Type 1 還是 Type 2 及理由。
