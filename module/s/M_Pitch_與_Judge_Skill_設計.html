Pitch 與 Judge Skill 設計

  • W8 期中 Midterm Pitch：各組報告 W7 完成的 MRD（15 分鐘 + 5 分鐘 Q&A）；同儕與教師依期中 評分標準 評分；Q&A 本身就是考試。鞏固 W1–W7，理論負荷刻意調輕，聚焦守住 MRD。
  • W16 期末 Final Pitch + Judge Skill：完整產品提案（market research → MRD → PRD → wireframe → risk → roadmap）；各組設計一個「Judge Skill」——能依 評分標準 維度（可行性 / 理論基礎 / AI 工藝 / 範疇紀律）評分他組 pitch 的 Claude Code skill。
  • 理論：Distributed Cognition（Hutchins）——評審是跨人類同儕 / AI 評審 / 評分標準 的分散認知系統；Inscription / Script（Akrich）——設計 Judge Skill 就是把自己的價值刻進一個會評判同學的人造物。
  • Flip Exercise｜Judge Skill + Peer Review Final：各組對所有他組 pitch 跑自己的 Judge Skill；全班彙整 Judge-Skill 分 + 同儕分 + 教師分為單一排名。四個獎：最可行 / 理論最扎實 / 最有創意用 Agentic AI / 最佳 Judge Skill（與同儕＋教師共識最一致）。呼應 W2 / W10 的 skill-building。
  • 小作業（期末）：繳交可運作的 Judge Skill + 反思「AI 評審抓到什麼人類漏掉的，反之亦然」。
  • 案例：Claude Build Day Hackathon 評審的三標準（可驗證性/真實影響/可部署性）幾乎對應這一堂 評分標準 四維；Opus 4.7 Claude Code Hackathon 的 MaestrIA「先做評估後做功能」（9 維對照 12 真實案例）就是學生摸索出來的 Judge Skill 版本。

進行方式

  • 各組 Pitch：期中 15′ 報告 + 5′ Q&A／期末完整提案；Q&A 就是即時考核，台下其他組同步用自己的 Judge Skill 跑分。
  • 跑 Judge Skill ＋ 彙整排名：各組把他組 pitch 丟進自己設計的 Judge Skill，當場匯出四維度分數；全班把 Judge-Skill 分、同儕分、教師分疊成單一排名，看哪一把「尺」跟共識最一致。

💬 討論／分享／反思

  • 配對互評：兩組互換 Judge Skill 的評分結果，比對「你的 AI 評審給我打的分」跟「我自己覺得的弱點」差在哪——是 AI 抓到我沒看到的範疇漏洞，還是 AI 漏掉了我引以為傲的理論基礎？
  • 一起收斂一題：「如果四個維度（可行性／理論基礎／AI 工藝／範疇紀律）只能留一個寫進 評分標準，你會留哪一個、砍掉哪三個為什麼？」——逼大家面對自己把什麼價值刻進了 Judge Skill（呼應 Inscription/Script）。
  • 寫下個人反思：各自寫一句「AI 評審抓到了什麼人類同儕漏掉的，反過來人類又抓到什麼 AI 漏掉的」，當作期末小作業反思的第一稿種子。
