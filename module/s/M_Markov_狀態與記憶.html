Markov 狀態與記憶

  • 一句話：Markov 性質 = 下一步只看當下狀態，不看更早的歷史。 AI agent 的每一步要不要只看當下、要不要外掛記憶，是 looping/harness 設計的核心抉擇。

核心

狀態（state）：描述「現在情況」的那組資訊。Markov 假設：「未來只取決於現在，與如何走到現在無關」——下一步機率 $P(\text{下一狀態}\mid\text{當前狀態})$ 不需要更早的歷史。

LLM 的兩難：模型本身沒有跨對話的長期記憶，它「記得」的只有塞進 context window 的東西（連回 Token 與分詞）。所以： - 純 Markov 式 agent：每一步只看「當前 context」就決定下一步。簡單、省 token，但會忘——上一輪辛苦消除的不確定性，下一輪可能又冒回來。 - 要長期一致：得外掛記憶（把關鍵狀態寫進筆記/資料庫，下一輪再讀回來），人為地把「歷史」塞回「當前狀態」。

三個設計抉擇（looping/harness 的核心）： 1. 狀態裡放什麼：放太少 → 失憶、來回鬼打牆；放太多 → token 爆掉、加噪稀釋（連回 Harness Engineering 與資訊熵：context 不是越多越好）。 2. 記憶放哪：塞進 context（短期、貴）vs 寫進外部儲存再檢索（長期、要設計取回機制）。 3. 每一輪怎麼更新狀態：哪些該保留、哪些該丟、哪些該壓縮成摘要——這就是 loop 的「狀態轉移」設計。

連回 Autoregressive 生成與取樣：autoregressive 是「把自己的輸出餵回自己」的短期 Markov 鏈；agent loop 把它放大成「把上一輪的結論餵回下一輪」。狀態設計好不好，決定 loop 會收斂還是鬼打牆。

💬 互動

  • 一起想一題：一個跑很多輪的 AI agent，做到第 8 輪忘了第 2 輪的關鍵決定，又重做一遍——問題出在「狀態」還是「記憶」？該怎麼補？

  • 反思：「AI 在長對話裡『忘記』前面講過的，不是它健忘，是那段已經滑出 context 了——我得幫它留住關鍵狀態。」
