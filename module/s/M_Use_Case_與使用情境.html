Use Case 與使用情境

  • 為何 vibe coding 時代反而更該學：User story 講「一句要什麼」，use case 講「完整一條走完的路，包含岔路和出錯」。AI 最常漏的不是主流程，而是例外與邊界——使用者點到一半關掉、輸入空白、網路斷線。用 use case 把這些「另一條路」事先攤開，AI 才不會只做出「順順走完一次」的 demo。

核心

Use Case = 一個角色為達成目標，與系統互動的完整流程，含三層： 1. 主要流程（happy path）：一切順利時的步驟序列。 2. 替代流程（alternate）：合理但不同的走法（用第三方登入、用優惠碼）。 3. 例外流程（exception）：出錯怎麼辦（密碼錯、付款失敗、逾時）。

結構欄位（輕量版即可）：角色、前置條件、觸發、主流程步驟、替代/例外、後置條件。

和 user story 的分工： - User story：小、一句、強調價值——適合排 backlog、餵單一功能給 AI。 - Use case：較大、一段流程、強調完整性——適合想清楚一個關鍵任務的全貌、抓出 AI 會漏的岔路。 - 實務常見：一個重要 use case 拆成多個 user story 來做。

vibe coding 接法：先寫 use case 把例外流程逼出來，那些例外就是你要額外丟給 AI 的需求，也是測試案例的金礦（連回 邊界與例外案例設計）。Demo 漂亮 ≠ 產品可用，差別幾乎都在例外流程有沒有處理。

💬 互動

  • 一起想一題：「線上點餐」的主流程三步就走完，但替代/例外有哪些？（缺貨、改地址、付款失敗、店家打烊）列五個 AI 容易漏的。

  • 反思：「我驗收 AI 做的東西，是不是只跑了 happy path？真正會出包的都在岔路上。」

  • 小作業：挑一個你要做的關鍵任務，寫一份 use case，至少列 3 條例外流程，標出哪些 AI 第一版最可能漏。
