資訊理論與不確定性

每條目標都是「一項能力 → 能解釋一個真實問題」。學這個不是為了背公式，是為了能回答你本來就好奇、而且天天踩到的事。

# 你會的能力 讓你能解釋的真實問題
1 解釋 entropy 就是「不確定性／還沒被消除的猜測空間」，資訊量＝消除了多少不確定性 為什麼老闆落落長的信常常沒新資訊，一句「你被資遣了」資訊量卻爆表？資訊量跟字數無關。
2 判斷一段對話裡 AI 手上的 context 夠不夠、不確定性集中在哪 為什麼同一個問題，我給三句背景它就答得準、我只丟一句它就亂編？context 不足＝它面對的 entropy 太高，只好用最可能的答案硬補。
3 拆解一次「AI 幻覺／亂補」是怎麼從不確定性產生的，並推論該補什麼 context 那次 AI 把我同事的名字張冠李戴、把沒發生的會議講得煞有其事——它不是笨，是我讓它在高不確定性下被迫生成。我當時少給了什麼？

不確定性是一種「猜測空間」，資訊量就是把它砍小

先備概念：entropy 是「平均不確定性」，公式是 $H = -\sum p_i \log_2 p_i$。這一堂不重推公式，只借它的直覺：分布越均勻、entropy 越高、越不可預測；餵對資訊就把分布壓尖、entropy 砍下來。

這一節的目的不是讓你會算 entropy，而是讓你用 entropy 的眼睛看 AI。讀完之後，看到 AI 亂講話，第一個念頭不會是「這 AI 真笨」，而是「它面對的猜測空間太大，我少餵了哪幾塊資訊？」

先用一個猜詞遊戲建立直覺。假設對方心裡想著一個職業，你要用是非題把它猜出來：

你問的問題 砍掉多少不確定性 拿到幾 bit
「是醫師嗎？」 幾乎沒砍（幾千種職業砍掉一種） ≈ 0 bit，爛問題
「是室內工作嗎？」 一刀砍掉約一半 ≈ 1 bit，好問題
「需要證照嗎？」 又砍一半 再 +1 bit

每問一個「砍一半」的好問題，就拿到 1 bit。如果職業有 16 種等可能，理論上 $\log_2 16 = 4$ 個好問題就收斂。重點不在你問了幾句話，在每一句砍掉多少猜測空間。

把這個直覺接到「資訊量跟字數無關」：

訊息 字數 消除的不確定性 資訊量
老闆落落長的勉勵信 800 字 你早就知道的事 趨近 0
「你被資遣了」 5 字 把你對未來的猜測空間整個翻掉 爆表
「明天 50% 降雨」 6 字 分布最均勻、最沒幫你決策 高 entropy，逼你再去查
「明天 100% 出太陽」 7 字 分布塌成一個尖峰 entropy ≈ 0，可直接行動

自己想一下：丟一枚公正硬幣，結果幾 bit？（答：1 bit，$\log_2 2 = 1$。最公平＝最不可預測＝資訊量最大。）

⚠️ 迷思攔截

迷思 為什麼錯 攔截方式
「報告寫越長＝資訊越多」 長度量的是字數，不是消除的不確定性 回扣「資遣信 vs 勉勵信」
「entropy 高是壞事」 entropy 是中性量尺，量的是「還沒被消除的猜測空間」，不是混亂或品質差 強調單位是 bit，是尺不是評價

資訊量不看你說了多少，看你砍掉對方多少猜測空間。AI 面對的猜測空間，就是它的 entropy。

學生閱讀｜這一段你自己讀就懂

上一個模組把 entropy 定成「平均還剩多少不確定性」。這一段只做一件事：把那把尺拿去量 AI。

AI 生成文字的方式，是一步一步猜下一個字。每一步它心裡都有一個「哪些字比較可能」的分布。 你給的背景資訊越足，那個分布就越尖——它幾乎知道該接什麼； 你給得越少，分布越平——它面對的 entropy 很高，但它仍然被要求給出答案， 於是它挑一個「看起來最合理」的答案填上去。

這就是幻覺的來源。它不是在說謊，是在高不確定性下被迫生成。 所以下次它亂講，第一個該問的不是「這 AI 怎麼這麼笨」，而是「我少餵了哪一塊資訊」。

把這把尺對準 LLM：context 不足＝高 entropy＝它只好硬補

LLM 在做的事，一句話：給定目前的上下文，吐出「下一個 token 的機率分布」，再從分布裡 sample。這個分布有它的 entropy——分布越平，模型越不知道該說什麼，sample 出來就越像亂編。幻覺不是品德問題，是高 entropy 下被迫生成的數學後果。

生成式 vs 判別式（一句話分清楚）：判別式模型是「在你給的選項裡選一個」（分類、是非），猜測空間小、容易驗證；生成式 LLM 是「從近乎無限的句子空間裡生一段」，猜測空間天生巨大，所以餵 context 砍 entropy 才是它能不能可靠的關鍵。

核心對照表：context 不足 → 高 entropy → 幻覺

你給的 context 模型對「答案」的分布 entropy 它的行為
只丟「我們上週那案子結論是什麼？」 一堆似是而非的答案機率差不多（均勻） 高 從均勻分布 sample → 亂編一個煞有其事的結論
加三句背景：客戶、爭點、上次決議 分布開始往某幾個答案集中 中 答得有方向，但細節可能還湊
把那份會議紀錄整份貼進去 分布塌成一個尖峰 ≈ 0 它只能照著紀錄講，幾乎不會錯

為什麼「同一個問題，給三句它就準、丟一句它就亂編」：你不是在跟一個「有時聰明有時笨」的人講話，你是在調節它面前那個分布的形狀。你每給一塊對的 context，就是替它砍掉一半猜測空間。 這正是 RAG／檢索／工具呼叫的本質：不是讓模型變聰明，是幫它把 entropy 壓低（深入工程做法見 Harness Engineering 與資訊熵）。

那次 AI 把同事名字張冠李戴、把沒發生的會議講得煞有其事——拆給主管看：模型手上對「這位同事叫什麼、那場會開了沒」的分布是均勻的，它沒有任何 bit 去塌縮這個分布，於是用「訓練資料裡最常見的名字／最像會發生的會議」硬補。它不是說謊，是在高不確定性下被你逼著生成。當時你少給的，就是那幾塊能砍掉一半的 context。

補充視角：模型「最常見的答案」從哪來、為什麼會系統性偏向某些答案，屬於訓練分布偏斜的問題，見 深度學習與 LLM 偏見來源；而把真訊息從一堆雜訊裡認出來，見 訊號與雜訊。

🎛 互動：餵 context，看它的猜測空間塌下去

同一個問題「這位受訪者最可能的職業是什麼？」。你每補一塊 context，它下一步的候選分布就被壓尖一點，entropy 就掉一截——幻覺不是它笨，是你讓它在高 entropy 下被迫生成。

⚠️ 迷思攔截

迷思 為什麼錯 攔截方式
「AI 出錯＝它笨／模型不夠強」 多數錯是 context 不足造成的高 entropy 硬猜，換更強的模型也救不了沒給的資訊 反問：你給它的 bit 夠它砍到尖峰了嗎？
「context 塞越多越好」 無關／矛盾的資料是加噪，等於問一堆爛是非題，反而把 entropy 加回去、稀釋邊際資訊量 準則是「每塊 context 的邊際資訊量」高，不是量大
「它講得很流暢，應該是對的」 流暢度由語言機率決定，跟事實無關；滑順但空泛常正是高 entropy 硬 sample 的徵兆 教主管把「流暢」和「有依據」分開看

幻覺＝context 不足讓它的 entropy 太高，它只好用最可能的答案硬補。主管的工作不是嫌它笨，是把它面前那個分布餵尖。

學生閱讀｜給足 context 不等於什麼都貼

「餵資訊」有一條界線：能砍掉不確定性的、而且可以外流的資訊才餵。 未公開的消息來源、個資、還沒發布的稿件，貼進外部 AI 服務就是外流， 這跟它答得準不準是兩回事。

實務上先問兩題：這塊資訊真的能幫它收斂嗎？如果它明天出現在別人的螢幕上，我會不會出事？ 兩題都過才貼。

主管視角：跟工程師對話、自己用 agent 的標準動作

把 entropy 當成你和工程師之間的共同語言。你不必會算，但你要會用它定位問題、問對問題。

該問工程師的三題（entropy 版） 1. 「這個 AI 功能下一步靠什麼資訊收斂？它的 context 視窗多大、我們的內部資料餵不餵得進去？」（→ 它有沒有足夠的 bit 去砍 entropy） 2. 「它亂答的時候，通常是哪一類不確定性沒被消掉——缺資料、缺工具、還是指令太鬆？」（→ 把幻覺定位成可修的 entropy 來源，而不是含糊的「AI 就是會錯」） 3. 「我們怎麼驗證它不是在高 entropy 下硬猜？有沒有讓它『不確定就說不知道、或去查』的機制？」（→ 不確定性的安全閥；誤判一旦放行的代價怎麼估，見 Confusion Matrix 與誤判代價）

自己用 agent／AI 的三個動作 1. 先餵高資訊量的 context：把最能「砍一半」的關鍵檔案、規格、限制、前情先給足，別丟一堆無關背景稀釋它。問自己：我給的這塊，能塌縮它的分布嗎？ 2. 能查的就讓它查：給它檢索或工具，等於授權它自己去問是非題、自己砍 entropy，不要逼它用記憶硬掰。 3. 可疑就追問來源：輸出很「滑順但空泛」時要它列依據——這是把它從「硬 sample」拉回「有 bit 支撐」。

界線提醒（呼應這一堂討論題、亦見 Harness Engineering 與資訊熵）：「給足 context」和「把商業機密貼給外部 AI」是兩回事。砍 entropy 要用對的、可外洩的資訊；機密走內部部署或先去識別化。收斂一個部門原則，而不是因噎廢食地什麼都不餵。

AI 會不會幫你做對事，多半不取決於模型多強，而取決於你有沒有把它下一步的 entropy 餵到夠低。主管的核心技能，是用 entropy 這把尺，把「它怎麼又亂講」翻譯成「我該補哪一塊 context」。
