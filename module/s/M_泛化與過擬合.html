泛化與過擬合

  • 一句話：泛化 = 在沒見過的新狀況也表現好；過擬合 = 把訓練資料背得太死，連雜訊都當規律，一換場景就垮。 好的 AI、好的 prompt，都要泛化而非死背。

核心

泛化（generalization）：模型的價值在於對沒看過的資料也準。死記訓練資料不算學會——背答案的學生換題就不會。

過擬合（overfitting）：模型把訓練資料的偶然細節、雜訊也學了進去，在訓練集滿分、一上真實世界就崩。徵兆是「訓練表現好得異常，實測很差」。 - 反面是欠擬合：模型太簡單，連訓練資料的規律都沒抓到。 - 目標是兩者之間的甜蜜點：抓住真規律、忽略雜訊（連回 訊號與雜訊 的訊號 vs 雜訊）。

為什麼這直接撐起 context / prompt engineering： 1. Few-shot 例子 = 一種「擬合」：你在 prompt 裡給的範例，模型會去「擬合」它們。例子選得偏／太特殊 → 模型過擬合到你的例子，把你沒料到的個案也套同一招。 例子要有代表性、要涵蓋變異（呼應 Sampling Theory 抽樣理論）。 2. Prompt 過度雕琢的陷阱：把 prompt 調到「在我這幾個測試案例上完美」，很可能是過擬合到那幾個案例——換真實輸入就破。要拿沒調過的新案例驗證（等於 ML 的「測試集」紀律）。 3. 「在我電腦上好好的」：demo 漂亮不代表會泛化。AI 產品上線翻車，常常就是把 demo 案例過擬合了。

管理者一句話：要求看 AI 在沒挑過的、真實分布的案例上的表現，不要被精心挑選的 demo 騙了。

💬 互動

  • 配對：各舉一個「在測試時很準、真實情境就失準」的 AI/規則例子，判斷是過擬合還是資料偏（或兩者）。

  • 反思：「我調 prompt 調到對我那幾個例子很順時，要停下來問——這是真的學會了，還是只是背了我的例子？」

  • 小作業：拿一個你調過的 prompt，找 3 個你「設計時沒想到」的新輸入測它，記錄它泛化得好不好。
