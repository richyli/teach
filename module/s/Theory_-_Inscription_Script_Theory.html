Inscription Script Theory

A short primer on Inscription / Script Theory: what it claims, where it sits in this course, and the questions it lets you ask about your own product.

Madeleine Akrich (1992); with Bruno Latour — "Designers inscribe an expected user into objects; objects then prescribe behaviour."

The core idea

Every artefact carries a script — a program of action that anticipates a particular user, environment, and purpose. To use the object is, in part, to play the role it has scripted for you.

  • Inscription = designers embed assumptions about the user into the object
  • De-scription = the analyst reads those scripts back out
  • Configuring the user (Woolgar) — every design implicitly defines who the user is allowed to be
  • The gap between the projected user and the actual user is where breakdown, workaround, and appropriation happen

Where this theory sits in this course

  • Supporting theory in W16 Final Presentation — optional stretch material, and a useful contrasting lens in those weeks.
  • It is never the week's Primary theory, so no report is assigned to it. It still earns marks when it does real work in a pitch.

Lens questions

When you face a product decision, ask: 1. Who is the assumed user inscribed in this artefact — and have I named them out loud? 2. What does this design prescribe that the user must do, know, or own? 3. Where is the gap between my projected user and the people who actually showed up? 4. Which user appropriations or workarounds are telling me my script is wrong?

Recommended reading

  • Akrich 1992, "The De-scription of Technical Objects" in Bijker & Law (eds.) Shaping Technology / Building Society — see Akrich 1992 De-Scription
  • Akrich & Latour 1992, "A Summary of a Convenient Vocabulary" — the shared glossary for scripts, antiprograms, delegation
  • Woolgar 1991, "Configuring the User: The Case of Usability Trials" — the canonical companion piece

Pair with Agentic AI

Three concrete moves for AI-assisted PM work: 1. Name the inscribed user — every Claude Skill, system prompt, and PRD assumes one; write that user as the first paragraph of the artefact 2. Run a de-scription drill — pick a popular Claude Skill, infer its assumed user from prompt + tool list, and check it against your own team's user 3. Audit appropriation signals — collect the workarounds, "wrong" prompts, and complaints; treat them as evidence the script is mis-aligned

⚠️ Pitfall: the AI inherits your inscriptions and amplifies them at scale — your unstated assumptions become the default user for everyone the model touches.

Discussion

  1. Pick a Claude Skill you have written (or used). De-scribe it: who is the inscribed user, and how does the assumed user differ from your real users?
  2. When users "misuse" your AI feature in productive ways, is that a script failure, a script success, or a new script being written by the user?
