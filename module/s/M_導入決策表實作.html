# 你會的能力 讓你能解釋的真實問題
1 填出一張含成本、風險、鎖定與退場的四路比較表 為什麼 SaaS 報價看起來最便宜，兩年後卻最貴？
2 拆解「總持有成本」裡看不見的那幾項（人月、整合、資料清理、退場） 為什麼 IT 說三個月做得完，實際上跑了一年？
3 判斷並為一條路辯護，同時說出這個判斷在什麼條件下會翻盤 我在會議上被問「為什麼不自己做」，我的答案撐得住幾個追問？

🤖 課前 AI 互動（10 分鐘，上課前完成）

先想好一個你真的在考慮的 AI 功能（自動上字幕、留言審查、稿件校對、讀者分群、內部知識問答……），然後貼這段：

我在評估要不要為〔功能〕導入 AI。請你分別以「買 SaaS」「接 API 自己包」「自建模型」「暫不導入」四條路，各列出三項容易被低估的成本，以及一項容易被低估的風險。請明確標示哪些是通則、哪些需要看我的組織規模才能判斷。

它的答案會很通用——通用就是它的價值：你要帶著這份通用清單來，現場把它換算成你們公司的數字。

進行方式

一、填四路表

每組選一個功能，填這張表。不准留空格，估不出來就寫「估不出來，要問誰」。

買 SaaS 接 API 自己包 自建 暫不導入
上線要多久 —
第一年現金支出 0
需要的內部人力（人月） 目前的人力成本
資料要送到哪裡 不外流
出錯時誰負責 現況的人
兩年後想換掉，帶得走什麼 —
這條路最大的風險 落後的風險

「暫不導入」那一欄一定要填。 它是四條路裡唯一免費的一條，也是最常被會議氣氛排除掉的一條。

二、補上隱形成本

把第一年現金支出那格改寫成兩年總持有成本，至少要加上四項：

  1. 整合：接上現有系統（CMS、CRM、廣告系統）的工時
  2. 資料清理：你的資料現在是能用的狀態嗎？沒有的話，清理誰做
  3. 驗收與監看：誰每週看它有沒有壞掉（回想 Confusion Matrix 與誤判代價：模型會安靜地錯）
  4. 退場：兩年後不用了，資料搬出來、流程改回去要花多久

多數組在這一步會發現數字翻倍以上。這一步就是這堂課的重點。

三、攻防

每組派一人當「提案人」，其他組當「主管會議」，各問一題：

  • 「為什麼不自己做？」／「為什麼不直接買現成的？」
  • 「這筆錢如果拿去請一個人，做得到同樣的事嗎？」
  • 「這個供應商明年漲價一倍，你怎麼辦？」
  • 「資料送出去，法遵那邊同意了嗎？」（連回 AI 地景與主管決策框架）
  • 「六個月後怎麼判斷這個決定錯了？」

提案人最後要補一欄：這個判斷在什麼條件下會翻盤。例如「如果三個月內找不到願意兼任的內部工程師，就從自建改成 API」。

四、收斂

各組一句話交代選了哪條路、以及翻盤條件。沒有翻盤條件的提案不算完成——那代表你沒有想過自己會錯。

⚠️ 迷思攔截

迷思 為什麼錯 攔截方式
「自建比較便宜，因為不用付月費」 人月成本通常遠高於訂閱費，而且是持續的；自建真正貴的是維護與人員流動 要求把人月換算成錢寫進表裡
「先買 SaaS 試試看，不好再換」 換不換得掉取決於資料與流程被綁多深，不是取決於合約長短 要求填「帶得走什麼」那一列
「暫不導入等於什麼都不做」 暫不導入是一個有成本、也有理由的正式選項——它買的是等技術成熟、等價格下降 規定那一欄不准留空
「這是 IT 的決定」 資料要不要外流、出錯誰負責、流程要不要改，都是主管的決定 攻防環節由非技術背景的人當提案人

與其他模組的關係

  • 理論在前：採購 vs 自建決策（四條路的取捨、ROI、鎖定）
  • 法規與風險：AI 地景與主管決策框架｜誤判成本怎麼算：Confusion Matrix 與誤判代價
  • 決定之後：變革管理與導入｜導入提案組裝工作坊

連結：採購 vs 自建決策｜AI 地景與主管決策框架｜Confusion Matrix 與誤判代價｜變革管理與導入｜導入提案組裝工作坊
