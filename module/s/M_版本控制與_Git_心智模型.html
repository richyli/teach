M 版本控制與 Git 心智模型

  • 為何 vibe coding 時代反而更該學：AI 會大刀闊斧地改你的程式——有時改好，有時把本來會動的東西改壞。沒有版本控制，你就沒有「回到上一個能動的版本」的後悔藥，一次壞掉可能整個專案毀了。Git 是 vibe coding 最重要的安全網：讓你敢放手讓 AI 大改，因為隨時退得回來。你不必背指令（AI 會下），但心智模型一定要懂。

核心

版本控制 = 幫專案存「時光快照」，隨時能回到任何一個過去的版本、看誰改了什麼、把不同人的修改合起來。

四個一定要懂的心智模型（不是背指令）： 1. Commit（提交）= 存一個快照：做到一個「能動的段落」就 commit 一次，附一句話說明改了什麼。commit 越頻繁，後悔藥越多。vibe coding 的鐵律：讓 AI 大改之前，先 commit。 2. Branch（分支）= 平行宇宙：想試一個沒把握的大改，開一條 branch 去玩，搞砸了直接丟掉、主線毫髮無傷；成功了再合併回去。「叫 AI 大改」就該在 branch 上做。 3. Rollback / Revert（回復）= 後悔藥：AI 把東西改壞了，一鍵回到上一個 commit。這就是你敢放手的底氣。 4. Remote / Push（遠端備份）= 雲端副本：推到 GitHub 等於異地備份，電腦壞了、檔案亂了都還在，也是和別人協作的共同基地。

為什麼「心智模型 > 指令」：你只要在腦中清楚「現在我在哪個版本、哪條分支、上一個安全點在哪」，具體指令交給 AI 下。搞丟方向感才是災難，不是不會打指令。

vibe coding 接法：(1) 開工先 git init；(2) 每個能動的小進展就 commit；(3) 重大實驗開 branch；(4) AI 改壞了就 revert 回上一個 commit——這套節奏讓你「敢讓 AI 亂試」，因為錯了零成本退回。沒有它，vibe coding 是在走鋼索沒有安全網。

💬 互動

  • 一起想一題：AI 連改了 5 個地方後整個跑不動，你也看不懂它改了啥。有版本控制 vs 沒有，你的處境差多少？

  • 反思：「我讓 AI 改程式前，有沒有先存一個『還能動』的安全點？還是改壞了只能從頭來？」

  • 小作業：替你的一個 vibe coding 專案 git init，養成「每個小進展 commit 一次」的習慣，並故意做一次「改壞 → revert 回去」演練。
