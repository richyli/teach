Claude Code 上手

🎯 學習目標

每條目標都是「一項能力 → 能解釋一個真實問題」。學這個不是為了學寫程式，是為了讓一個會動手做事的 agent 第一次在你電腦上跑起來、處理你真的在做的工作。

# 你會的能力 讓你能解釋的真實問題
1 區分 agent／chatbot／workflow，說明 Claude Code 為何屬 agent 為什麼說 Claude Code 不是「比較聰明的聊天框」？因為它會讀你的檔、寫檔、跑指令，還會臨場判斷。
2 操作完成安裝並下一個結構清楚的指令，用三段式（背景／任務／格式）跑一段真實工作 為什麼同一個指令，我跑出來爛、別人跑出來好？結果好不好取決於你怎麼問——你負責下指令＋驗收，它負責執行。
3 判斷在一次任務中，哪一步該放行讓它自己跑、哪一步該按煞車自己接手 不會寫程式的人到底能不能用？——拆解一次真實任務，你會發現關鍵不是技術，是「何時放手、何時把關」的判斷力。

註：上述 lecture/demo 約 35′，其餘 10′ 留給下方分享與反思。

💬 討論／分享／反思

  • 配對分享：兩人互看剛跑出來的結果，各指出「AI 幫上忙的一處」與「需要你介入修正的一處」。
  • 課堂收斂：彙整「Claude Code 最容易出錯的地方」前三名，貼上班級工具箱。

  • 反思：「如果這是我每週的真實工作，我會不會固定用它？阻礙我的是介面、信任、還是不知道它能做什麼？」

  • 小作業：把一段真實工作用 Claude Code 處理，記錄它對／錯各一處，並寫一句「下次我會怎麼改提示」。

連結 / 關係

  • 後續模組（先修鏈）：Claude Code 串工作流——這一堂教「安裝＋第一個指令」，串工作流教「設計 skill、接 MCP、批次產製」。先會這課再上那課。
  • 放大版：Vibe Coding 做小工具——同一套「描述需求＋驗收＋迭代」心法，從處理文件放大到做出並發布一個能用的小工具。
  • 背後的不確定性工程：Harness Engineering 與資訊熵——為什麼「給足 context」這麼重要，用 entropy 把它講透。
  • 每週輪替的分享場：工具箱分享——把本課做出的成果帶去分享、互評、歸檔成班級工具箱。
  • 何時放手的判斷：adaptive autonomy、cognitive offloading——煞車鍵＝人類把關，判斷與學習要留給自己。
  • 學生自學版：SP Agentic AI 實作（與 Claude Code 串工作流 合併的實作軌自學包）。
